# 开发与交付

## 架构与开发思路

界面采用 Gradio Blocks，`ui/` 负责页面和交互；`services/` 负责校验、任务编排及索引事务；`adapters/` 封装 GPT-SoVITS 的命令和推理接口；`models/` 定义持久化结构。环境向导负责依赖、资源和配置诊断，不承担训练编排。

UI 与模型分属两个独立 Python 环境。启动脚本固定调用包内解释器，子进程使用明确参数、工作目录和超时。保留已验证 v2Pro 的内部目录，避免只复制入口脚本而遗漏模型、词典和工具依赖。

路径解析集中在 `services/project_paths.py`，业务数据归属和删除事务由存储服务处理。项目内路径相对于根目录，不能用开发电脑路径或固定目录层级推导。

线程锁与进程文件锁共同保证 GPU 串行。推理进程可缓存同一音色模型，其他 GPU 任务取得锁后释放空闲推理资源。Windows Job Object 管理应用及其子进程生命周期，失败、超时及退出都需释放自有进程；不终止身份未知的端口占用者。

## 日常验证

从项目根使用包内解释器运行与修改相关的测试；模型任务与占用 GPU 锁的测试不要并行。

```powershell
./runtimes/ui/python.exe -m unittest discover -s tests
./start.bat --check
./start.bat --diagnose
```

测试替身、真实 GPU 操作、浏览器检查与人工听测分别记录。跳过项不计为通过，诊断 READY 不代表真实训练已完成。原始报告、截图和命令输出放在 `data/logs/diagnostics/` 或 `data/tmp/`，产品文档只保留经过整理的结论和用法。

## 搬目录、更新与回滚

停止应用，在完整副本内执行预览：

```powershell
./runtimes/ui/python.exe scripts/migrate_project_paths.py --from-root "旧项目完整路径"
# 核对预览后，在相同命令后追加 --apply。
./runtimes/ui/python.exe scripts/migrate_project_paths.py --rollback "data/migrations/事务ID"
```

`config/path-migration.json` 是已有数据的本地路径映射，升级时保留，源码分发时不带入。模型解释器路径修复使用 `scripts/relocate_engine_runtime.py`，默认预览，追加 `--apply` 才写入并备份。存储归属迁移使用 `scripts/migrate_storage.py`，同样先预览再应用。

升级在副本中替换应用文件并验证，不用空索引覆盖旧 `data/`。恢复失败或文件已经被后续修改时，迁移工具拒绝强制覆盖；依据具体事务报告处理。

## S7 交付流程

界面优化在 S6 完成后，再以冻结版本执行 S7。当前仅完成文档精简，以下交付步骤仍需以实际结果验收。

- [x] 精简产品文档，移除团队任务、个人周志、历史方案和环境证据附件；保留使用、设计、数据和开发说明。
- [ ] 冻结发布版本、配置模板与依赖锁定清单。
- [ ] 在独立 staging 目录按明确包含清单组装源码包和运行包。
- [ ] 核对第三方源码、Python 依赖、模型和音频工具的来源及再分发许可，保留必要 LICENSE/NOTICE。
- [ ] 生成文件大小、SHA-256、版本说明，实测压缩与解压空间需求。
- [ ] 在中文或空格路径副本中验证环境诊断、启动和真实工作流；确认不读取原开发目录。
- [ ] 验证最终界面的合成、试听、下载、搜索、复用、删除及重启恢复；代码有变化时补相关回归。
- [ ] 完成新音频人工听测，并分别记录本机迁移与接收电脑验证结果；未取得接收机结果时明确待验证。

源码包包含应用代码、必要工具、配置模板、依赖锁定、产品文档和许可证。完整运行包按许可额外组装独立解释器、引擎及基础资源；只包含推理资源的包不能标为完整训练包。资源不齐时提供来源、目标位置和校验方式，不标为完整离线包。

默认排除 `_archive/`、`.git/`、本地音频与权重、用户索引、失败实验、缓存、诊断报告、迁移备份、`config/engine.local.json`、`config/path-migration.json` 和秘密配置。已授权的演示材料须显式列入交付清单。

文档删除只作用于当前工作树，不清除 Git 历史。公开发布应从整理后的包含清单生成新交付物，不附带开发仓库历史；需要公开现有 Git 历史时，另行审查其中的旧文档与提交信息。
