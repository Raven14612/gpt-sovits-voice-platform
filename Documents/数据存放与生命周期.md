# 数据存放与生命周期

## 主要文件

所有下列路径相对于项目根目录。索引保存稳定 ID 和相对路径，运行时统一解析到当前根目录。

| 文件 | 位置 | 用途 |
|---|---|---|
| 导入的长音频副本 | `data/datasets/<dataset_id>/source.wav` | 平台内原始输入；不修改外部原件 |
| 处理参数与可选截取音频 | `data/datasets/<dataset_id>/processing/<task_id>/` | 记录保留范围，供切分使用 |
| 切分子音频 | 同一处理目录下 `slices/` | ASR、试听和训练输入 |
| 自动识别标注 | 同一处理目录下 `asr/slices.list` | 与切片一一对应的识别初稿 |
| 确认标注和情绪 | `data/datasets/<dataset_id>/annotations/<revision_id>/` | `corrected.list`、`emotions.json`；旧版本位置以索引及归属记录为准 |
| 特征与校验清单 | `data/datasets/<dataset_id>/features/<task_id>/` | BERT、HuBERT、SV、语义特征、32k 音频、输入副本和 `manifest.json` |
| 训练配置、归属和检查点 | `data/training/` | 独立实验目录，具体位置以训练计划为准 |
| 音色文件组 | `data/voices/<voice_id>/` | GPT `.ckpt`、SoVITS `.pth`、参考音频及档案 |
| 最终合成语音 | `data/outputs/` | 成功合成并验证的独立 WAV |
| 业务索引 | `data/index/` | `datasets.json`、`voices.json`、`history.json`、`tasks.json` |
| 日志、缓存、清理事务 | `data/logs/`、`data/cache/`、`data/tmp/`、`data/deletions/` | 定位失败、暂存下载、恢复未完成删除 |

除了原音频、切片、标注、两个权重和成品，**特征、训练配置、参考音频、索引与归属记录**也是主要工作文件。仅复制两份权重不等于备份完整音色档案。

## 两套独立生命周期

音色组清理依据材料归属执行，覆盖平台保存的原音频、切片、各版标注、情绪、特征、训练实验、检查点、最终权重和参考材料。移入回收站只改变可用状态；彻底删除才清理文件与关联索引。

清理不会删除该音色已经合成的成品、外部原始音频、共享引擎或基础模型。无法确认归属的缓存和孤立文件不会按名字猜测删除。存在共享归属冲突或越界链接时拒绝不安全清理。

成品由 `history.json` 独立管理，包含名称、备注、合成文本、参数和来源快照。删除成品会清理其 WAV、记录和平台准备的下载副本；这不会反向修改音色组。

删除事务先暂存目标、提交索引，再清理文件。提交前失败尝试回滚；提交后未清完的内容由“重试未完成清理”或启动恢复继续处理。不得仅因文件被占用就报告全部成功。

## 校验和状态

标注必须与切片一一对应。特征提取记录输入哈希及输出清单，训练准备再次校验；输入改变后需重新确认并提取特征。只有两阶段训练成功、产物校验通过后才注册可用音色。

任务状态使用 `pending → running → succeeded/failed/cancelled`；输入校验或锁冲突也可从 `pending` 进入失败。启动恢复把遗留运行任务标为失败、等待任务标为取消，不自动重放。

`TaskRecord` 保存 `input_params`、`result_id`、`output_info`、`error_code`、阶段和日志。合成历史保存 `voice_id`、`text`、`emotion`、`speed_factor`、`fragment_interval`、`output_path`、`status`，并增加显示名称、备注和来源快照。成功状态必须有对应的有效文件，动画或进程退出本身不构成成功证据。

## 备份与迁移

先停止任务并退出应用，再成套备份 `data/` 与本地配置，避免索引和文件不一致。移目录使用现有路径迁移工具；保留业务迁移记录供恢复。环境报告及运行日志可能包含真实路径，默认只作本地诊断，不随源码或产品文档发布。
