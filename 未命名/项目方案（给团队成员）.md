# 轻量级音色克隆项目：我们要做什么

> 这份说明是给项目成员看的执行版。它把 GPT-SoVITS 整合包里的思路，转换成我们真正准备开发的学生项目。  
> 参考图片和示例音频仍放在本文件夹的 `attachments/` 中，仅作界面和流程参考。

## 先说清楚三件事

### 1. GPT-SoVITS 不是我们开发的

我们参考了一个可以运行的 GPT-SoVITS 整合包，主要是为了快速弄清楚：需要什么音频、会产生哪些文件、如何训练、如何合成。

这个整合包和 GPT-SoVITS 开源项目都属于外部依赖，不属于我们的自研成果。我们不会把整合包直接塞进项目仓库，也不会把它的路径写死在代码里。项目运行时，由使用者在自己的电脑上配置 GPT-SoVITS 目录。

我们自己要开发的是：

- 简单好用的 Gradio 页面；
- 音频、数据集、音色和生成结果的文件管理；
- 训练和合成任务的状态显示；
- 对 GPT-SoVITS 的统一调用接口；
- 出错时能看懂的提示和日志。

### 2. 先以 50 系电脑跑通完整流程

CXY 的 RTX 50 系电脑作为主验证设备，先完成：

```text
音频导入 → 切分 → 中文识别 → 人工校对 → 特征提取
→ SoVITS/GPT 训练 → 保存音色 → 加载权重 → 合成语音
```

其他成员使用 40 系电脑，不需要等待 50 系环境才能写代码。LJQ 单独负责验证 40 系能否使用同一套项目完成推理；40 系训练能否跑通属于增强验证，不影响我们先完成 50 系主流程。

### 3. 关闭并行推理

我们默认一台电脑一次只执行一个 GPU 任务。训练、ASR、特征提取和 TTS 合成不能同时抢显存。页面可以显示“等待中/执行中/成功/失败”，但没有真实进度时不能编造百分比。

## 用户最终怎么用

用户不需要懂 GPT-SoVITS 的内部结构，只需要按页面操作：

1. 上传自己的、已经获得授权的人声音频。
2. 点击处理，系统自动切分并进行中文语音识别。
3. 在页面上检查并修改识别文字，再给每段音频人工选择情绪标签。
4. 选择数据集，点击“生成音色”，等待特征提取和训练完成。
5. 输入一个音色展示名和一个内部特征名，保存音色。
6. 在文本生成页面选择音色、情绪和文字，点击合成。
7. 在结果页面播放、下载、查看历史或复用以前的参数。

如果电脑暂时不能训练，仍然可以走保底方式：直接上传一段 3–10 秒的参考音频并填写准确文字，用零样本方式先完成合成。这个保底方式不等于训练成功，页面和文档中要区分清楚。

## GPT 和 SoVITS 分别做什么

可以把它们简单理解为两位配合工作的“演员”：

- GPT 更关注“怎么读”：停顿、节奏、语气和大致的说话方式；
- SoVITS 更关注“用谁的声音读”：音色、发音和最后的声音还原。

真正合成时，除了目标文字和训练后的权重，还要提供一段参考音频及其文字。参考音频不是可有可无的装饰，而是模型确认说话人和当前说话风格的重要输入。

## 页面一：音频数据处理

用户可以上传一段长的人声文件。MVP 默认它已经是纯人声，不强制加入人声分离和降噪，避免把项目做得过大。

页面要完成：

1. 播放原始音频；
2. 允许简单填写首尾时间，去掉开头和结尾的空白；
3. 按固定参数切成较短的语音片段；
4. 用 FunASR 中文大模型识别每段文字；
5. 让用户逐条修改识别结果；
6. 给每段音频人工选择 `中性 / 开心 / 悲伤` 标签；
7. 保存数据集、切片、标注文件和情绪文件。

第一版固定使用以下切分参数，普通用户不调整：

| 参数 | 值 | 简单解释 |
|---|---:|---|
| `threshold` | `-34` | 低于这个音量时，作为可能的静音位置 |
| `min_length` | `4000 ms` | 每段至少尽量达到 4 秒 |
| `min_interval` | `300 ms` | 两个切点之间至少间隔 0.3 秒 |
| `hop_size` | `10 ms` | 每隔多久检查一次音量 |
| `max_sil_kept` | `500 ms` | 切完后最多保留约 0.5 秒静音 |

情绪标签由人确认，不能把“文字内容看起来积极”直接当成“说话时一定开心”。以后如果加入 LLM，它只能先给建议，用户仍然可以修改；LLM 自动分类不作为当前 MVP 的通过条件。

## 页面二：音色训练与仓库

这个页面展示还没有完成训练的数据集。用户选择数据集后，系统按固定顺序执行：

```text
检查数据 → 文本特征 → HuBERT/音频特征 → 语义 Token
→ SoVITS 训练 → GPT 训练 → 打包音色档案
```

普通用户不需要理解每一步，也不需要修改训练参数。页面只显示当前阶段、真实日志和最终结果。

50 系主轨的第一版训练参数沿用已经验证过的设置：

| 模块 | 参数 | 默认值 |
|---|---|---:|
| SoVITS | batch size | `4` |
| SoVITS | 训练轮数 | `8` |
| SoVITS | 文本模块学习率权重 | `0.4` |
| SoVITS | 保存频率 | 每 `4` 轮 |
| GPT | batch size | `4` |
| GPT | 训练轮数 | `15` |
| GPT | 保存频率 | 每 `5` 轮 |
| GPT | DPO | 关闭 |
| 两者 | 只保留最新权重 | 开启 |
| 两者 | 并行推理 | **关闭** |

参数不是跨所有显卡的保证。40 系如果显存或依赖不合适，LJQ 记录实际结果，不要为了追求表面一致而修改代码硬适配。

### 音色名称和文件

用户保存音色时填写两个名称：

- 展示名：用户在页面上看到的名字，例如“温柔女生”；
- 特征名：项目内部用于区分本次训练的名字，例如 `gentle_female_v1`。

系统为音色生成稳定的 `voice_id`，并把 GPT 权重、SoVITS 权重、参考音频、参考文字、情绪标签、来源数据集和训练日志放在同一个音色档案下。目录名不直接使用用户输入的中文名称，避免重名和路径问题。

## 页面三：文本生成语音

用户选择音色、输入文字，再选择情绪：

- 中性：默认必须可用；
- 开心：只有存在合法开心参考片段时才可用；
- 悲伤：只有存在合法悲伤参考片段时才可用。

情绪的实现方式是更换同一个人的参考片段，不是新增一个万能的“情绪旋钮”。如果没有对应参考，按钮要置灰并说明原因。

参考音频选择规则：优先选择 3–10 秒、文字不为空、没有明显截断的片段；不能简单地无条件取“最长的第一段”。用户后续可以手动更换参考片段。

合成时始终关闭并行推理。文本长度、语速和句间停顿需要做基本校验；合成失败时不写入成功历史。

## 页面四：合成结果管理

每次真实合成成功后，结果保存到对应音色的结果目录，并写入历史记录。用户可以：

- 播放 WAV；
- 下载 WAV；
- 查看文本、音色、情绪、语速、停顿和创建时间；
- 复用历史参数；
- 删除结果。

MVP 先保证 WAV。MP3、公网分享、水印、敏感词拦截和账号系统都不属于当前任务。

## 我们四个人怎么分工

### CXY：50 系主轨和最终验收

负责产品范围、50 系真实运行、训练参数、模型加载、真实音频证据和最终验收。不再独自承担全部页面和后端代码。

### LHY：后端与文件管理

负责数据结构、音频/音色/历史服务、任务状态机、子进程调用、日志、错误处理、原子 JSON 和重启恢复。可以没有 GPU，先用测试替身把接口和状态写好。

### LJQ：40 系兼容

负责一台代表性 40 系电脑的环境记录、适配器探测、零样本推理和兼容报告。40 系训练属于增强任务，不能把未经验证的结果写成“支持”。

### WGX：前端与体验

负责四页 Gradio 页面、导航、共享状态、按钮禁用、情绪置灰、错误提示、浏览器测试、截图和录屏。不直接写模型命令。

## 现在的工程结构

```text
Project/
├─ app.py                    # 唯一启动入口
├─ adapters/                 # GPT-SoVITS 外部适配器
├─ config/                   # 配置样例，本机配置不提交
├─ models/                   # 数据结构和统一错误
├─ services/                 # 业务逻辑和任务编排
├─ ui/                       # 四页 Gradio 页面
├─ data/                     # 数据集、音色、输出和索引
├─ tests/                    # 不依赖 GPU 的测试
└─ Documents/                # 当前计划、契约、分工和废案
```

## 我们如何判断“完成”

- 50 系：数据处理、训练、权重加载和真实合成全部跑通，才叫完整主轨；
- 40 系：至少一台机器通过项目入口真实合成，才能叫推理兼容；
- 40 系训练：只有完整训练并加载新权重成功，才能叫训练兼容；
- 所有“完成”都必须能找到真实日志、音频、JSON 或截图；
- 测试替身可以验证代码逻辑，但不能冒充真实 GPU 结果；
- 如果环境不支持某一步，就显示失败原因并记录降级，不伪造成功。

## 本阶段明确不做

- 不复制或修改第三方整合包核心代码；
- 不声称支持所有 40/50 系显卡；
- 不做并行推理；
- 不做模型级音色—韵律解耦；
- 不做自动情绪分类的正式验收；
- 不做水印、敏感词、登录、积分、充值、公网分享和音色市场；
- 不把计划中的功能写成已经完成。

## 接下来马上做什么

4. WGX 开始四页 UI 壳和五种任务状态。
5. 四人通过统一契约交接，不互相等待对方先拥有同样的显卡。
