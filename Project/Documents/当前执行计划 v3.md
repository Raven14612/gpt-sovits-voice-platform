# 轻量级语音克隆项目当前执行计划 v3

> 生效日期：2026-09-04  
> 项目形态：学生团队、本地 Windows GPU、Gradio 单体应用  
> 主验证设备：CXY 的 RTX 5060 Laptop GPU  
> 兼容验证设备：LJQ 负责的一台 RTX 40 系代表机

## 1. 项目结论

本项目不拥有 GPT-SoVITS 或任何第三方整合包。项目开发内容是：

```text
自研 Gradio UI
→ 自研 Python services、数据档案、任务状态和错误处理
→ 自研 GPT-SoVITS 适配器
→ 用户在本机单独准备的 GPT-SoVITS 运行环境
```

第三方整合包只用于快速了解输入、输出、参数和运行链路，不复制进入项目仓库，不宣称为自研，也不在业务代码中写死其目录。

## 2. MVP 路线

主路线：

```text
导入授权音频
→ 固定参数切分
→ FunASR 中文识别
→ 人工校对文本与人工情绪标签
→ 特征提取
→ SoVITS 与 GPT 固定参数微调
→ 保存音色档案及一对权重
→ 串行加载并合成
→ 播放、下载、历史管理
```

保底路线：合格的 3–10 秒音频 + 准确参考文本，可绕过训练，直接做零样本合成。保底路线用于环境不支持训练时维持产品可用性，但不能冒充完成了微调训练。

MVP 情绪只做人工标签和人工参考片段。标签为 `neutral`、`happy`、`sad`；默认 `neutral`。未来可让 LLM 给出可修改建议，但不进入当前验收。

## 3. 固定技术边界

- 唯一入口为 `Project/app.py`，使用 Gradio Blocks。
- 不增加 Vue、React、FastAPI、数据库、Redis、Celery 或云服务。
- UI/业务 Python 与模型运行时分离；模型任务通过配置后的解释器和适配脚本执行。
- GPU 任务全局串行；关闭并行推理，禁止同时训练和推理。
- 不修改 GPT-SoVITS 核心模型代码来赶工。
- 不承诺支持所有 NVIDIA GPU，只对有真实证据的轨道作兼容声明。
- 不实现水印、敏感词系统、登录、积分、充值、音色市场或公网分享。

## 4. 四页产品结构

| 页面 | MVP 职责 |
|---|---|
| 音频数据处理 | 上传、播放器、首尾裁剪、固定参数切分、ASR、文本校对、人工情绪标签 |
| 音色训练与仓库 | 选择数据集、显示训练阶段、保存音色名称与权重档案、删除/查看音色 |
| 文本生成语音 | 选择音色、输入文本、选择可用情绪、串行合成、高级语速/停顿 |
| 合成结果管理 | 播放、下载、查看历史、复用参数、删除结果 |

运行时侧栏一次只显示一个完整页面。环境状态放在侧栏底部，不作为第五页。

## 5. 团队职责与决策权

### CXY：产品与 50 系引擎负责人

- 冻结范围、参数和最终验收口径。
- 维护 50 系真实模型链路和证据。
- 提供适配器真实命令、输入输出样例和失败条件。
- 审核第三方边界、演示口径和最终合并。
- 不包揽后端和前端的日常实现。

### LHY：后端与集成负责人

- 独立设计并实现 schemas、services、JSON 索引和任务状态机。
- 实现可配置的模型适配器、子进程、日志、超时和错误转换。
- 使用测试替身完成无 GPU 自动测试；真实模型证据由 CXY/LJQ 提供。
- 对后端代码质量和集成入口负责。

### LJQ：40 系兼容负责人

- 选择一台 40 系代表机，记录真实环境。
- 验证统一适配器在 40 系上的探测和真实推理。
- 输出兼容问题、显存限制与建议配置。
- 40 系训练属于增强验证；先完成推理兼容。

### WGX：前端与体验负责人

- 独立实现四页、导航、状态、State 和浏览器交互。
- 只调用 services，不直接拼 GPT-SoVITS 命令。
- 使用明确的空状态/测试返回开发页面；不得内置假成功和假音频。
- 对页面可用性、截图和浏览器冒烟负责。

## 6. 四周执行安排

### Week 1：接口、双轨基线与工程壳

**CXY**

- 先用 50 系整合包 Web UI 生成一条新的真实 WAV，补齐权重加载证据；再根据页面、源码和日志反查 adapter 调用。
- 固定 50 系整合包的探测、切分、ASR、训练、推理命令和 I/O；无法从现有证据确认的项目标记“待实测”，不猜命令。
- 审核并冻结 `engine-adapter-v0.1`。

**LHY**

- 建立 `schemas.py`、`AppError`、service 模块和适配器接口。
- 建立 `engine.example.json`、环境探测与任务状态机。
- 为无 GPU 路径编写自动测试。

**LJQ**

- 先通过 40 系整合包 Web UI 建立可复核的代表机基线和操作证据，再尝试项目 adapter 复现。
- 至少完成 GPU/PyTorch/FFmpeg/引擎目录探测。
- 争取完成一条真实零样本 WAV。

**WGX**

- 完成四页工程壳、侧栏切换和共享 State。
- 完成空、等待、执行、成功、失败五种视觉状态。

**Week 1 过线**

- 50 系先通过整合包 Web UI 产生真实 WAV，并提交页面、日志、文件证据；随后启动项目 adapter 复现。adapter 尚未复现时，不得写“项目调用已通过”。
- 后端接口可导入、可测试，路径没有写死。
- 四页可切换且不依赖 GPU 开发。
- 40 系有真实环境结论；Web UI 与项目 adapter 的结论分开记录，未完成推理时记录阻塞，不伪装通过。

### Week 2：数据处理与训练任务

**CXY**：冻结切分、ASR、特征提取、SoVITS/GPT 训练参数；运行一次 50 系完整训练闭环。  
**LHY**：实现数据集档案、训练编排、日志、权重归档、恢复和原子索引。  
**LJQ**：完成 40 系项目内零样本推理；可选验证缩小训练任务。  
**WGX**：完成音频页和音色训练页，显示真实阶段而非虚构百分比。

**Week 2 过线**：50 系从数据集产生可加载的 GPT/SoVITS 权重；项目正确保存音色档案。40 系训练不是阻断项。

### Week 3：合成、情绪参考与结果闭环

**CXY**：验证训练权重、中性与人工情绪参考，执行连续合成回归。  
**LHY**：完成串行 TTS、历史、复用、失败隔离和索引恢复。  
**LJQ**：在 40 系通过项目入口真实合成，记录显存和失败条件。  
**WGX**：完成合成页、结果页、情绪置灰、历史复用和删除。

**Week 3 过线**：形成“音色 → 合成 → 结果 → 历史 → 复用 → 重启恢复”的真实闭环。

### Week 4：稳定性、兼容结论与答辩

**CXY**：最终验收、范围冻结、主 Demo 和证据索引。  
**LHY**：错误加固、日志、测试、安装与配置说明。  
**LJQ**：提交 40 系兼容报告和备用证据。  
**WGX**：视觉精修、浏览器兼容、截图、录屏和操作说明。

## 7. 兼容性声明分级

| 声明 | 必须具备的真实证据 |
|---|---|
| 50 系完整支持 | 数据处理、训练、权重加载和合成均在代表机真实通过 |
| 40 系推理兼容 | 至少一台 40 系通过项目入口真实合成 |
| 40 系训练兼容 | 至少一台 40 系完成训练并加载新权重合成 |

如果只完成前两项，对外统一表述为：

> 项目已在 RTX 50 系验证完整训练与推理闭环，并在代表性 RTX 40 系设备验证推理兼容；40 系训练仍为实验性支持。

## 8. 统一交接格式

每次交接只发：

```text
[任务ID]
产物：<仓库路径>
证据：<日志/音频/截图路径>
结论：通过 / 部分通过 / 阻塞
已知限制：<一至三条>
下游可开始：<任务ID或无>
```

任务超过 1.5 人日仍无最小产物时，必须拆分；阻塞超过半天写入 `Decisions.md`，由对应领域负责人提出处理方案，CXY裁定范围与最终验收影响。
