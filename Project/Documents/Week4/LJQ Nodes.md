# LJQ Week 4 节点：算法与模型

## LJQ-N1：演示参数冻结

**目标**  
冻结答辩演示用的音色、文本、情绪样本和推理参数，避免临场临时更换。

**输入**

- Week 3 合成参数表与双条件对照记录。
- CXY 授权素材、5 条固定回归文本。
- 已保存且稳定的 `voice.json` 列表。
- [GPU Environment Baseline.md](../GPU%20Environment%20Baseline.md) 全组矩阵。

**工作**

- 选定主 Demo 音色（至少 1 个中性稳定）及备用音色。
- 选定演示用固定文本（从 5 条回归中择 1–2 条主展示，其余作备用）。
- 确认演示情绪样本是否存在；无则写入“置灰说明”口径。
- 冻结 `speed_factor`、`fragment_interval`、语种等演示参数。
- 指定主 Demo 机器与 GPU 轨道（Track A/B）。
- 输出演示参数包给 CXY 与 WGX。

**输出**

- 演示参数包（音色 ID、文本、路径、参数、Demo 机）。
- 置灰/可演示情绪清单。
- 参数变更记录（相对 Week 3）。

**三个指标**

- **哪些人的工作会影响我？** Week 3 算法记录是硬依赖；CXY-N1 演示范围是软依赖。
- **我需要交付什么内容？** 演示参数包与情绪清单。
- **谁需要等待我完成该工作？** LJQ-N2 等回归；CXY-N2 等脚本；LJQ-N3 等资源检查。

**完成判定**

- 参数包中路径在本机可访问且已验证。
- 未授权或不稳定音色不得进入主 Demo。

**AI 参考提示词**

```text
请根据Week 3参数与授权清单，整理答辩演示参数冻结包。

输入：<voices.json摘要>、<5条回归文本>、<GPU矩阵>、<情绪refs状态>

输出：
1. 主Demo voice_id与reference路径；
2. 主/备演示文本；
3. 冻结推理参数；
4. 可演示情绪与置灰项；
5. 主Demo机器与Track A/B。

不要选未验证音色；不要临时改参数不写记录。
```

## LJQ-N2：最终回归样音

**目标**  
完成 5 条固定回归文本的最终 WAV 与听测记录，作为质量与答辩备用证据。

**输入**

- LJQ-N1 演示参数包。
- LHY 集成版 `tts_service.synthesize`。
- CXY 回归听测表模板。

**工作**

- 对 5 条固定文本各生成 1 条最终 `output.wav`（本机真实推理）。
- 同一主 Demo 音色连续 3 次合成，记录稳定性。
- 填写听测表：可懂度、音色相似、失真、漂移（描述性）。
- 打包 WAV 路径、日志、history 条目对照。
- 标记质量不达标条目及是否影响 Demo。

**输出**

- 5 条回归 WAV 包 + 3 次连续合成记录。
- 听测表。
- 质量风险说明。

**三个指标**

- **哪些人的工作会影响我？** LJQ-N1 是硬依赖；LHY 集成版是硬依赖。
- **我需要交付什么内容？** 回归 WAV、听测表和风险说明。
- **谁需要等待我完成该工作？** CXY-N3/N4 等证据；CXY-N2 等备用降级素材。

**完成判定**

- 全部 WAV 来自本次运行，非 Week 3 旧文件冒充。
- 听测为人工勾选，非 AI 打分。

**AI 参考提示词**

```text
请设计Week 4最终回归样音执行与记录方案。

输入：<演示参数包>、<5条回归文本>、<听测表模板>

输出：
1. 每条文本合成步骤；
2. 连续3次合成记录模板；
3. WAV/日志/history对照；
4. 不达标判定与Demo影响说明；
5. 禁止复用旧WAV的检查方法。

不修改模型核心；不把preview当output。
```

## LJQ-N3：答辩前资源检查

**目标**  
在彩排/答辩前确认 GPU、模型、权重、FFmpeg 和 ASR 状态可用。

**输入**

- LJQ-N1 演示参数包。
- 环境基线表与主 Demo 机信息。
- CXY-N2 演示脚本时间节点。

**工作**

- 运行 `nvidia-smi`、PyTorch CUDA 检查、模型目录与权重完整性检查。
- 确认 FFmpeg、ASR 模型、GPT-SoVITS 入口可启动。
- 清理占 GPU 的无关进程；确认单任务串行策略仍生效。
- 对演示参数包执行 1 次完整冒烟（试听或短句合成）。
- 记录检查时间与结果；异常时通知 CXY 触发应急预案。

**输出**

- 答辩前资源检查表（含时间戳）。
- 冒烟日志。
- 阻断/非阻断问题清单。

**三个指标**

- **哪些人的工作会影响我？** LJQ-N1 是硬依赖；CXY-N2 彩排时间是软依赖。
- **我需要交付什么内容？** 检查表、冒烟日志和问题清单。
- **谁需要等待我完成该工作？** CXY-N4 等终审；WGX-N4 等录屏前确认。

**完成判定**

- 检查项均来自本机命令输出，非推测。
- 冒烟在答辩前 24 小时内至少执行一次（可重复）。

**AI 参考提示词**

```text
请生成答辩前GPU/模型资源检查清单。

输入：<演示参数包>、<GPU Environment Baseline>、<演示脚本时间>

检查项：
- nvidia-smi、torch.cuda、显存空闲；
- GPT-SoVITS目录、权重、FFmpeg、ASR；
- 单任务串行；
- 1次短句冒烟。

输出：检查表、通过/失败判定、阻断问题、通知CXY的应急建议。
不要跳过本机命令。
```

## LJQ-N4：算法边界与答辩要点

**目标**  
整理对外说明用的算法能力边界、失败样例和答辩 Q&A 要点。

**输入**

- Week 3 双条件对照与失败场景。
- LJQ-N2 听测结果。
- CXY-N3 已知限制草案。

**工作**

- 撰写算法边界说明：零样本、参考音频质量、情绪=换参考、无训练/解耦。
- 整理 3–5 个真实失败样例（OOM、文本过长、参考缺失等）及用户可见提示。
- 准备答辩 Q&A：相似度、情绪效果、ASR 依赖、40/50 环境差异。
- 与 CXY 对齐口径，删除百分比或“准确率”表述。
- 标注自动情绪为实验/未纳入主 Demo（若存在）。

**输出**

- 算法边界说明（1–2 页）。
- 答辩 Q&A 要点。
- 失败样例与提示对照表。

**三个指标**

- **哪些人的工作会影响我？** LJQ-N2/N3 是软依赖；CXY-N3 是软依赖，可并行起草后合并。
- **我需要交付什么内容？** 边界说明、Q&A 和失败样例表。
- **谁需要等待我完成该工作？** CXY-N4 等答辩材料；全员统一对外说法。

**完成判定**

- 无“模型级解耦已实现”等夸大表述。
- Q&A 答案与现场功能一致。

**AI 参考提示词**

```text
请根据Week 3对照实验与听测结果，起草算法边界说明与答辩Q&A。

输入：<双条件对照>、<听测表>、<已知限制>

输出：
1. 能力边界（做什么/不做什么）；
2. 5个常见答辩问题与如实回答；
3. 3–5个失败样例与用户提示；
4. 需删除的夸大表述；
5. 自动情绪/实验功能口径。

禁止编造相似度百分比或解耦指标。
```
