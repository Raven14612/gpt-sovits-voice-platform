# CXY Week 4 节点：数据、评测、文档与终审

## CXY-N1：最终 DoD 与验收清单

**目标**  
冻结 Week 4 范围、最终验收清单和 Demo 冻结规则，防止答辩前功能蔓延。

**输入**

- 总计划、`newplan.md` 最终验收清单。
- Week 3 验收结果、问题清单与 `contract-v2.0`。
- Week 3 已知限制草案。

**工作**

- 定稿 Week 4 DoD 与最终验收清单（环境、页面、数据、合成、文档）。
- 明确五类典型失败必须可演示：未授权、音频无效、ASR 失败、模型未加载、显存不足/超时。
- 定义答辩前 48 小时 Demo 冻结规则与允许修复的范围（仅演示阻断）。
- 列出功能保留顺序与应急降级口径（与风险表一致）。
- 明确不验收的新增功能项。

**输出**

- Week 4 最终 DoD。
- 最终验收清单（可勾选版）。
- Demo 冻结规则与允许修复范围说明。

**三个指标**

- **哪些人的工作会影响我？** Week 3 验收结果是软依赖；可先依据总计划起草，再根据阻断项调整。
- **我需要交付什么内容？** 最终 DoD、验收清单和冻结规则。
- **谁需要等待我完成该工作？** LHY-N1、WGX-N1 等加固范围；CXY-N2/N3/N4 等脚本与矩阵基线。

**完成判定**

- 全员确认 Week 4 不加主功能。
- 验收清单每项可对应到证据类型（文件/日志/截图/测试）。

**AI 参考提示词**

```text
请依据项目总计划、newplan最终验收清单和Week 3结果，起草Week 4最终DoD。

必须包含：
- 全新实例全流程；
- pytest与GPU测试分开标记；
- 五类典型失败提示；
- 8–10分钟演示与答辩材料；
- 48小时Demo冻结规则；
- 功能保留顺序与OOM降级口径。

明确不做：新功能、训练、解耦、水印、SaaS、夸大指标。
只起草文档，不把计划写成已完成。
```

## CXY-N2：演示脚本、分镜与应急预案

**目标**  
产出可执行的 8–10 分钟演示脚本、录屏分镜和现场应急方案。

**输入**

- CXY-N1 最终 DoD。
- LJQ-N1 演示参数包（音色、文本、情绪样本路径）。
- Week 3 完整产品链路。
- 风险表与功能保留顺序。

**工作**

- 编写 8–10 分钟演示讲稿，对齐 newplan 10 步流程。
- 编写录屏分镜：每步画面、操作、口播要点、预计时长。
- 编写应急预案：OOM、ASR 失败、跨页失败、情绪无样本、浏览器播放失败。
- 指定主 Demo 机与备用证据（预跑 WAV、截图、日志）。
- 组织一次内部走读，标记易卡顿步骤。

**输出**

- 演示讲稿。
- 录屏分镜表。
- 应急预案（含降级话术）。

**三个指标**

- **哪些人的工作会影响我？** CXY-N1 是硬依赖；LJQ-N1 演示参数是软依赖，可先写框架后填入路径。
- **我需要交付什么内容？** 讲稿、分镜和应急预案。
- **谁需要等待我完成该工作？** WGX-N4 等录屏；LJQ-N3 等答辩前检查；CXY-N4 等终审彩排。

**完成判定**

- 讲稿逐步对应真实 UI 与功能，不含未实现能力。
- 每条应急预案有明确触发条件与对外说法。

**AI 参考提示词**

```text
请为单体Gradio语音克隆项目编写8–10分钟答辩演示脚本与录屏分镜。

输入：
- 10步演示流程；
- 演示参数包：<LJQ冻结内容>；
- 风险表与降级顺序。

输出：
1. 分步讲稿（操作+口播）；
2. 分镜表（画面/时长/证据）；
3. 应急：OOM、ASR失败、跨页失败、无情绪样本、浏览器问题；
4. 必须口头说明的项目边界。

禁止写未实现功能；禁止夸大相似度或解耦。
```

## CXY-N3：功能—证据矩阵与已知限制

**目标**  
建立每项对外宣称功能与真实证据的对应关系，并定稿已知限制文档。

**输入**

- CXY-N1 验收清单。
- Week 1–3 证据与 LJQ-N2 最终回归 WAV。
- LHY-N2 测试报告、LHY-N3 全新实例记录。
- LJQ-N4 算法边界说明；WGX-N4 终稿截图。

**工作**

- 维护功能—证据矩阵：功能描述 → 负责人 → 证据路径 → 验收状态。
- 汇总已知限制：零样本、情绪参考切换、无训练、无解耦、无公网分享、ASR 依赖等。
- 核对 README/PPT 草稿与矩阵一致，删除夸大表述。
- 标注未完成或实验性能力（如自动情绪）不得进入主 Demo。

**输出**

- 功能—证据矩阵。
- 已知限制文档（供 README 与 PPT 引用）。
- 文档一致性抽检记录。

**三个指标**

- **哪些人的工作会影响我？** CXY-N1 是硬依赖；LHY-N2/N3、LJQ-N2/N4、WGX-N4 是软依赖，随交付逐步补齐。
- **我需要交付什么内容？** 矩阵、限制文档和抽检记录。
- **谁需要等待我完成该工作？** CXY-N4 等终审；LHY-N4 等 README 对齐。

**完成判定**

- 矩阵中“已通过”项均有可追溯证据。
- 限制文档与现场功能无矛盾。

**AI 参考提示词**

3. README/PPT需删除的夸大表述清单；

## CXY-N4：终审彩排、验收签字与 Demo 冻结

**目标**  
组织最终彩排，完成终审验收并在答辩前 48 小时冻结 Demo。

**输入**

- LHY-N3 全新实例验证记录。
- WGX-N3/N4 浏览器与录屏素材。
- LJQ-N2 回归样音与 LJQ-N3 资源检查。
- CXY-N2 脚本、CXY-N3 矩阵。
- LHY-N1 五类失败演示结果。

**工作**

- 按最终验收清单逐项预演（全新实例 + 目标浏览器）。
- 执行 8–10 分钟完整彩排，记录卡顿与口误。
- 抽查五类典型失败与应急降级话术。
- 确认 README、视频、PPT 与现场一致。
- 发出最终通过/部分通过/失败结论；启动 48 小时 Demo 冻结。
- 冻结后仅受理“演示阻断”修复，由 CXY 排优先级。

**输出**

- 最终验收表（签字/确认记录）。
- 彩排问题清单与修复优先级。
- Demo 冻结公告与变更日志。

**三个指标**

- **哪些人的工作会影响我？** LHY-N3 是硬依赖；CXY-N2/N3、WGX-N4、LJQ-N2/N3 在终审前必须齐备。
- **我需要交付什么内容？** 验收表、彩排记录、冻结公告。
- **谁需要等待我完成该工作？** 全员等待答辩材料定稿；冻结后开发仅修阻断项。

**完成判定**

- 全新实例主链路现场走通。
- 冻结后无新增主功能合并。
- 部分通过项有书面限制说明，答辩时不隐瞒。

**AI 参考提示词**

```text
请根据Week 4最终DoD生成终审彩排与验收脚本。

输入证据：
- 全新实例日志；
- pytest/GPU测试报告；
- 浏览器播放下载结果；
- 五类失败演示；
- 回归WAV与矩阵；
- README/视频/PPT路径。

输出：逐步验收表、彩排计时、通过/部分通过/失败判定、冻结后变更规则、阻断问题优先级。
禁止预录WAV替代现场主链路（OOM降级除外且须说明）。
```
