## 当前任务队列

## 现在立刻做什么

先选定一台真实 40 系电脑，完成环境基线表。你可以继续只通过 40 系整合包 Web UI 操作；不要先做训练，也不要复制 CXY 的 50 系路径。按 [Web UI 整合包取证指南](../环境/WebUI整合包取证指南.md) 记录页面字段、控制台日志和输出目录，先把“这台机器到底能不能被项目识别”说清楚。

### LJQ-W1-01：40 系代表机环境基线（P0，可立即开始）

- **工作**：选择一台实际 40 系机器，记录 GPU、显存、驱动、Python、Torch、CUDA、FFmpeg、GPT-SoVITS 来源和模型情况。启动脚本、`webui.py`、`config.py` 和 Web UI 页面共同作为信息来源；页面能操作但命令/路径无法确认时写“待实测”，不猜。
- **产物**：`Documents/环境/LJQ-40series-baseline.md` 和原始命令输出文本。
- **通过**：所有版本来自真实命令；不复用 CXY 的 50 系记录。
- **下游**：LJQ-W1-02、CXY-W1-03。

**可直接交给 AI 的提示词**

```text
请阅读 Project/Documents/环境/GPU兼容矩阵.md、Project/Documents/契约/engine-adapter-v0.1.md 和 Project/Documents/成员任务/LJQ.md。

我要在一台真实 RTX 40 系 Windows 电脑上填写环境基线。请给我一份逐项检查清单和 PowerShell 命令，检查：GPU/显存/驱动、Python 路径和版本、Torch/CUDA/GPU 可见性、FFmpeg、GPT-SoVITS 来源与入口、预训练权重、ASR 模型。

要求：每一项都要记录命令原始输出；无法确认就写未测；不要复用 50 系结果；不要执行来源不明的下载和删除命令。
请输出基线表模板、证据文件命名方式和常见失败的下一步。
```

### LJQ-W1-02：统一适配器探测（P0）

- **输入**：LHY 的 adapter 骨架和 `engine.example.json`。
- **工作**：先按取证指南保存 40 系 Web UI 页面和控制台证据，再只修改本机配置运行 `probe_environment`；记录路径、编码、依赖和 GPU 问题。项目探测是补充验证，不要求先弄清整合包所有内部命令。
- **产物**：探测日志、问题清单和必要的复现步骤。
- **通过**：业务源码没有为 40 系单独硬编码；结果能区分可用、缺失和不兼容。
- **下游**：LHY 修复、CXY 验收。

**可直接交给 AI 的提示词**

```text
请阅读 engine-adapter-v0.1.md 和当前 Project/adapters 代码。

我的 40 系本机配置如下：
<填写 engine_root、python_path 和配置文件路径>

任务：先用 40 系 Web UI 和本机命令完成环境取证，再运行 probe_environment，判断配置、Python、Torch、CUDA、GPU 和 FFmpeg 是否可用。不要因为 Web UI 能打开就直接判定项目 adapter 可用。
请输出：运行命令、预期字段、实际结果记录表、失败分类和应交给 LHY 的问题描述。

不要修改业务源码，不要把 40 系判断写死在 UI，不要把“探测通过”写成“推理通过”。
```

### LJQ-W1-03：40 系零样本推理（P1）

- **工作**：先在 40 系 Web UI 使用授权短参考和准确文本生成一条真实 WAV，并保存页面截图、控制台日志、权重/输出文件列表；再尝试通过项目拟采用的 adapter 路径复现，两种结果分开写。
- **产物**：WAV、日志、耗时、峰值显存和配置摘要。
- **通过**：可播放且来自 40 系本机，页面证据、日志和输出文件相互对应；失败时提交完整日志仍算完成“兼容结论”，但不算推理兼容通过。Web UI 成功不能直接等同于项目 adapter 成功。

**可直接交给 AI 的提示词**

```text
请基于当前 GPT-SoVITS 版本和 engine-adapter 契约，设计一次 40 系零样本推理验证。第一步允许只通过 Web UI 完成；只有拿到页面字段、源码位置、日志和输出文件后，才设计 adapter 复现。

真实输入会由我填写：运行时路径、参考 WAV、参考文本、目标文本和输出路径。
请输出：Web UI 取证步骤；若证据足够，再给最小调用方式；关闭并行推理的参数；耗时/显存/退出码记录表；WAV 可播放检查方法以及失败排查顺序。证据不足的命令或路径标记“待实测”。

禁止使用旧 WAV 冒充本次结果，禁止编造成功，禁止修改模型核心，禁止把 Web UI 成功写成 adapter 成功。最终结论必须区分“Web UI 真实推理通过”“adapter 真实推理通过”“执行失败但原因明确”“尚未验证”。
```

## Week 2–4 领导任务

- Week 2：验证 40 系切分、ASR、项目内零样本推理；资源允许再做小规模训练实验。
- Week 3：连续真实合成、显存和异常场景测试，提交推理兼容结论。
- Week 4：完成 40 系兼容报告、支持边界和备用演示证据。
