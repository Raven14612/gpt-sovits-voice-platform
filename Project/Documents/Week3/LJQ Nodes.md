# LJQ Week 3 节点：算法与模型

## LJQ-N1：中性合成基线与 TTS 参数

**目标**  
将 Week 2 试听参数扩展为正式文本合成参数，确认中性音色稳定出声。

**输入**

- Week 2 试听参数表与 `tts_service` 骨架。
- CXY-N1 契约草案。
- 已保存的合法 `voice.json` 与固定回归文本。

**工作**

- 确认 `synthesize` 相对 `generate_preview` 的参数差异（文本长度、输出路径、超时等）。
- 确认中性参考（`emotion_refs.neutral` 或主 reference）的选用规则。
- 记录推荐默认值：`speed_factor`、`fragment_interval`、语种、采样率。
- 用已保存音色对 1 条固定文本执行中性合成冒烟。
- 记录耗时、显存、日志与可接受的质量下限（描述性，不用百分比）。

**输出**

- 正式合成参数表。
- 与 `tts_service.synthesize` 的字段对照。
- 至少 1 条中性 `output.wav` 冒烟记录。

**三个指标**

- **哪些人的工作会影响我？** Week 2 算法记录是硬依赖；CXY-N1 是软依赖，收到后对齐字段名。
- **我需要交付什么内容？** 合成参数表、字段对照和冒烟记录。
- **谁需要等待我完成该工作？** LHY-N1 等封装参数；LJQ-N2/N3 等情绪与验证基线。

**完成判定**

- 参数有源码入口或真实日志来源。
- 冒烟 WAV 来自本机本次 `synthesize` 调用。

**AI 参考提示词**

```text
请对照本地GPT-SoVITS源码和Week 2试听记录，整理Week 3正式合成参数表。

输入：<Week2试听参数>、<contract-v2.0草案>、<voice.json样例>

输出：
1. synthesize相对generate_preview的参数差异；
2. 中性参考选用规则；
3. speed_factor/fragment_interval/语种默认值与安全范围；
4. tts_service字段对照；
5. 1条固定文本冒烟步骤与记录模板。

不修改模型核心，不宣称模型极限字数。
```

## LJQ-N2：情绪映射与 emotion_refs 规则

**目标**  
定义手动情绪参考切换的业务规则与 UI 置灰条件。

**输入**

- LJQ-N1 合成参数。
- Week 2 参考音频规范。
- CXY 授权素材与同说话人多情绪片段（若有）。

**工作**

- 定义情绪标签与 `emotion_refs` 键的映射：中性、开心、悲伤；愤怒/惊讶仅在有样本时启用。
- 定义切换逻辑：选中情绪 → 选用对应 `path` + `text`；缺失则置灰且不可提交。
- 定义与 `voice_service` 保存时 `emotion_refs` 字段的一致性要求。
- 输出给 LHY 的选用算法和给 WGX 的胶囊置灰规则。
- 明确本周不做自动文本分类作为正式能力。

**输出**

- 情绪映射表。
- `emotion_refs` 校验与选用规则。
- 前端置灰/启用条件说明。

**三个指标**

- **哪些人的工作会影响我？** LJQ-N1 是硬依赖；CXY 授权清单是软依赖。
- **我需要交付什么内容？** 映射表、选用规则和 UI 条件说明。
- **谁需要等待我完成该工作？** LHY-N1 等合成选用；WGX-N1 等胶囊 UI；CXY-N2 等听测维度。

**完成判定**

- 无 `emotion_refs.happy` 时开心胶囊必须置灰。
- 规则可编码，不依赖“用户自己猜”。

**AI 参考提示词**

```text
请基于GPT-SoVITS零样本参考切换思路（仅借鉴，不整仓引入）和以下voice.json样例，起草情绪映射规则：
<粘贴样例>

输出：
1. 情绪标签与emotion_refs键映射；
2. synthesize时如何选用path+prompt_text；
3. 缺失参考时的置灰与AppError；
4. 给WGX的胶囊显示规则；
5. 明确自动分类为可选实验、默认关闭。

不要编造相似度百分比或模型级情绪旋钮。
```

## LJQ-N3：项目内真实合成验证

**目标**  
确认 `tts_service.synthesize` 生成的 `output.wav` 来自本项目的真实 GPT-SoVITS 调用。

**输入**

- LJQ-N1/N2 参数与映射。
- LHY-N1 可调用的 `synthesize`。
- CXY 固定回归文本与已保存音色。

**工作**

- 使用统一音色和回归文本执行项目内合成。
- 对比 Week 2 `preview.wav` 基线与合成输出路径、参数差异。
- 记录路径、参数、耗时、显存与日志。
- 协助排查 OOM、文本过长、音色无效、GPU 忙碌和模型加载问题。
- 至少完成 1 条中性合成和 1 条不同文本的合成验证。

**输出**

- 项目内真实 `output.wav` 验证记录（≥2 条）。
- 合成通过/失败清单。
- 排错说明。

**三个指标**

- **哪些人的工作会影响我？** LJQ-N1/N2 是硬依赖；LHY-N1 是硬依赖；CXY 回归文本是软依赖。
- **我需要交付什么内容？** 验证记录、日志和排错说明。
- **谁需要等待我完成该工作？** CXY-N4 等算法证据；LJQ-N4 等真实失败经验。

**完成判定**

- 记录可追溯到本次 service 调用。
- 没有复用 Week 2 `preview.wav` 冒充合成输出。

**AI 参考提示词**

```text
请设计项目内output.wav验证方案。

对比：
- Week 2 preview基线；
- 当前tts_service.synthesize输出。

输出：
1. 统一voice_id与回归文本；
2. 验证步骤及通过条件；
3. 路径、参数、耗时、显存、日志模板；
4. 识别Mock或静态WAV的方法；
5. OOM/文本过长/音色无效/GPU忙碌排查。

不修改TTS核心，不把preview当output证据。
```

## LJQ-N4：双条件对照与合成失败场景

**目标**  
完成轻量双条件对照实验，并整理合成阶段真实失败为用户提示依据。

**输入**

- LJQ-N1/N2/N3 的真实记录。
- LHY 的 `AppError` 列表。
- CXY-N2 失败用例草案。

**工作**

- 在固定 `voice_id`、固定文本、固定引擎下执行对照：
  - 只换 `emotion_refs`（至少中性 vs 一种有样本的情绪）；
  - 或只改 `speed_factor` / `fragment_interval` 各 1 组。
- 记录效果：明显 / 较弱 / 无效 / 失真 / 音色漂移（描述性）。
- 整理合成阶段失败：文本空、未选音色、GPU 忙碌、重复提交、OOM、超时、参考缺失、历史写入冲突。
- 区分“合成失败”和“历史不应写入成功”。

**输出**

- 双条件对照记录表（含 WAV 路径与听测结论）。
- 合成失败场景表。
- `AppError` 对照建议。

**三个指标**

- **哪些人的工作会影响我？** LJQ-N3 的真实验证是硬依赖；LHY 错误列表和 CXY-N2 是软依赖。
- **我需要交付什么内容？** 对照记录、失败场景和错误码对照。
- **谁需要等待我完成该工作？** CXY-N4 等实验结论与用例补全；LHY 可据此完善错误处理。

**完成判定**

- 对照实验有真实 WAV，结论如实描述，不夸大解耦效果。
- 无合法多情绪素材时，对照可只做韵律（语速/停顿），不阻断 MVP。

**AI 参考提示词**

```text
请根据以下真实日志设计Week 3双条件对照与合成失败场景：
<粘贴日志>

对照要求：
- 固定voice_id+文本+引擎；
- 只换emotion_refs 或 只改speed/fragment_interval；
- 记录明显/较弱/无效/失真/音色漂移。

失败表格：所属阶段、触发条件、AppError code、用户提示、是否写历史、复现方法。
覆盖8至12个高概率问题；无情绪样本时允许只做韵律对照。
不宣称完成模型解耦或准确率。
```
