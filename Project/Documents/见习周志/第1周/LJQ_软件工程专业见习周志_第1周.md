## 见习内容

本周是轻量级音色克隆项目的第一周，我主要负责 RTX 40 系显卡兼容轨的准备、环境检查方法整理以及后续推理验证方案设计。小组中 CXY 使用 RTX 50 系显卡，其余成员主要使用 40 系显卡。两类显卡可能需要不同的 PyTorch 和 CUDA 组合，如果简单复制同一个整合包，可能出现显卡无法识别、依赖冲突或运行速度异常。因此，小组决定不强行统一每个人的完整 Python 环境，而是统一项目代码、模型版本、接口字段和测试方法，再分别记录 50 系与 40 系的真实结果。

周一，我参与阅读项目需求和新的分工说明，了解系统的四个主要页面以及完整工作流程。项目需要把授权音频切成短句，使用 FunASR 识别中文，由用户校对文字并人工标注中性、开心或悲伤，再进行特征提取和 GPT、SoVITS 训练，最后使用音色权重合成语音。考虑到 40 系训练所需显存和环境尚未确认，本周兼容轨的最低目标不是立即完成全套训练，而是先弄清代表机的硬件、驱动、Python、PyTorch、CUDA、FFmpeg 和 GPT-SoVITS 来源，并争取完成一条真实零样本语音。

周二，我整理了环境基线检查项目和命令。系统层面需要通过 `nvidia-smi` 记录显卡型号、显存和驱动版本；框架层面需要记录 Python 路径、PyTorch 版本、PyTorch 内置 CUDA、`torch.cuda.is_available()` 和实际设备名称；音频链路需要检查 FFmpeg；模型层面需要确认 GPT-SoVITS 的来源、版本、预训练模型、ASR 模型和启动入口。所有结果必须来自代表机真实命令，不能直接照抄 50 系电脑的环境，也不能只写“应该可以运行”。环境记录还要保存失败信息，例如缺少哪个模型、哪个 DLL 无法加载、显存是否被其他程序占用，为后端适配器和最终兼容报告提供依据。

周三，我参与讨论了项目的兼容性声明方式。过去笼统地写“支持 40 系和 50 系显卡”并不严谨，因为不同设备可能只通过其中一部分功能。新的标准把结论分成三个层次：50 系完整支持需要真实通过数据处理、训练、权重加载和合成；40 系推理兼容需要至少一台代表机通过项目入口生成真实 WAV；40 系训练兼容则需要代表机完成训练并加载新权重合成。只有满足相应条件，才能在 README 和答辩中使用对应说法。如果 40 系只能推理，就如实写“推理兼容，训练仍为实验性支持”，避免作没有证据的保证。

周四，我配合小组梳理统一适配器的测试方法。项目将 GPT-SoVITS 根目录和模型 Python 路径放在本机配置中，适配器读取配置后完成环境探测。40 系测试时只更换自己的配置，不修改 UI 和 services 源码。如果必须为 40 系单独修改大量业务代码，说明适配层设计不合理。本周计划的第一轮探测将重点检查路径是否存在、解释器能否运行、Torch 是否识别 GPU、错误输出是否完整以及中文路径是否影响启动。推理测试则使用获得授权的 3—10 秒短参考、准确参考文本和固定目标文本，记录输出 WAV、耗时、显存和日志。

周五，我整理了 40 系兼容轨可能遇到的风险及处理顺序。首先是 PyTorch/CUDA 与显卡不匹配，此时优先按照实际 GPT-SoVITS 版本选择官方推荐组合，而不是修改模型核心；其次是显存不足，需要关闭其他占用显存的软件、缩短文本并保持单任务串行；再次是预训练权重或 ASR 模型缺失，应明确显示缺失项，不使用旧文件代替新结果；最后是 40 系环境与 50 系输出结构不同，需要把差异反馈给 LHY，由适配器处理，而不是在页面中加入显卡判断。本周完成了兼容测试范围、环境表字段、验收等级和问题反馈方式的确定。真实 40 系环境数据和零样本 WAV 需要在选定代表机后继续补充，当前不能把兼容性写成已经通过。

## 见习心得

本周的主要收获是理解了软件兼容测试不能只看“程序是否打开”。对于语音模型项目，即使 WebUI 能启动，也不代表切分、ASR、训练和推理都能正常工作；即使在一台 40 系显卡上成功，也不能代表所有 40 系型号都没有问题。可靠的兼容结论必须说明测试设备、环境版本、执行功能和证据范围。把“完整支持、推理兼容、训练兼容”分开后，项目的表述更加真实，也方便后续逐步增加验证范围。

我还认识到，测试人员并不是等开发完成后简单点击页面。兼容轨需要在前期参与配置格式、错误输出和接口设计，否则后端可能只适合开发者自己的电脑。通过代表机的真实失败日志，可以帮助小组发现路径写死、版本假设、编码问题和显存限制。失败本身也不是没有成果，只要能够稳定复现、说明原因并提出下一步，它就是有效的工程证据。

目前我的不足是还没有完成代表机的完整环境记录，对 GPT-SoVITS 不同版本在 40 系上的推荐依赖也需要通过实际来源进一步确认。下周我会优先提交真实基线，运行项目适配器探测，并争取完成一条零样本 WAV。在推理稳定之前不急于测试训练；如果遇到问题，将保存完整命令、退出码和日志，与 LHY 一起判断应该修改配置、适配器还是环境说明。
