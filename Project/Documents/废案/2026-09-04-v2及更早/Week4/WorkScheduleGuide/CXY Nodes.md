# CXY Week 4 节点：核心开发与终审

> 角色：核心开发 + 唯一决策者（前端精修 + 演示算法轨 + 终审）

## CXY-N1：最终 DoD 与冻结规则

**目标**  
冻结答辩范围，给出可检查的最终验收清单与降级规则。

**输入**

- 总计划与 Week 4 总览。
- Week 3 验收结果与已知限制清单。

**工作**

- 汇总 10 步演示链路的最终验收项，每项写明证据类型。
- 列出五类典型失败：未授权、音频无效、ASR 失败、模型未加载、显存不足/超时。
- 定义冻结规则：答辩前 48 小时停止加功能，只修演示阻断级缺陷。
- 定义现场降级预案：OOM 时播放同版本预跑 WAV 并口头说明。
- 在 `Decisions.md` 记录冻结时间点与降级规则。

**输出**

- Week 4 最终 DoD 与验收清单。
- 五类典型失败清单。
- 冻结与降级规则。

**三个指标**

- **哪些人的工作会影响我？** Week 3 验收结果是软依赖；可立即起草。
- **我需要交付什么内容？** 最终 DoD、失败清单、冻结与降级规则。
- **谁需要等待我完成该工作？** LHY-N1 等失败清单；本人 N2/N3 等冻结范围。

**完成判定**

- 每项验收都能指向文件、日志或截图。
- 冻结时间点明确且已写入台账。

**AI 参考提示词**

```text
请为答辩周起草最终DoD与冻结规则。

输入：项目总计划、Week 4总览、Week 3已知限制清单。

输出：
1. 10步演示链路对应的最终验收项与证据类型；
2. 五类典型失败清单（未授权、音频无效、ASR失败、模型未加载、显存不足/超时）及期望提示；
3. 答辩前48小时冻结规则与“演示阻断级缺陷”的判定标准；
4. 现场OOM降级预案与口头说明话术；
5. 需要写入Decisions.md的冻结与降级决议行。

不要新增功能范围；不要夸大能力；不要把计划写成已完成。
```

## CXY-N2：主题精修与四态统一

**目标**  
在不改结构的前提下把四页视觉与状态反馈收敛到可答辩水平。

> 本节点接管原 WGX-N1/N2。视觉工作超过 1 人日立即停止扩展。

**输入**

- Week 3 集成版四页。
- 页面展示稿（作为视觉参考，不作为结构依据）。
- CXY-N1 冻结范围。

**工作**

**A. 主题与布局**

- 统一 `theme.css`：浅色紫蓝主色、卡片圆角、间距与字号层级。
- 统一侧栏当前项高亮、按钮主次样式、表单对齐。
- 修正明显错位、溢出与滚动问题。

**B. 四态统一**

- 四页的空、加载、成功、失败四态使用统一组件与文案风格。
- 失败态统一展示 `AppError` 的 `message`，必要时可展开 `detail`。
- 加载态必须反映真实执行，不使用假进度条。
- 环境状态区显示真实检测结果，缺失项显示“未配置”。

**输出**

- 终稿 `theme.css` 与页面样式调整。
- 四态标准说明（组件、文案、颜色）。
- 四页四态截图。

**三个指标**

- **哪些人的工作会影响我？** CXY-N1 是软依赖；可立即开始。不阻塞 LHY 的失败加固。
- **我需要交付什么内容？** 终稿主题、四态标准与截图。
- **谁需要等待我完成该工作？** 本人 N4 等页面证据；WGX-N1 据此做浏览器兼容（非阻断）。

**完成判定**

- 四页视觉一致，无明显错位。
- 四态齐全且失败态可读；不出现假进度或固定成功状态。
- 超过 1 人日仍不稳定时，保留信息层级与交互，停止继续精修并在台账记一行。

**AI 参考提示词**

```text
请为Week 4的Gradio四页做视觉精修与四态统一方案（不改结构、不加功能）。

当前状态：<粘贴theme.css与页面截图说明>

输出：
1. 浅色紫蓝主题的CSS变量（主色、辅色、背景、边框、圆角、间距、字号层级）；
2. 侧栏当前项高亮、按钮主次、表单对齐的统一规则；
3. 四页空/加载/成功/失败四态的统一组件与文案模板；
4. AppError展示方式（message为主，detail可展开）；
5. 环境状态区真实检测结果与“未配置”显示规则；
6. 明显错位/溢出/滚动问题的排查清单；
7. 需要截图的位置与文件名。

约束：不换技术栈、不加页面、不使用假进度条或固定成功状态；
若精修超过1人日，请给出“保信息层级、停止扩展”的收口方案。
```

## CXY-N3：演示参数冻结与最终回归

**目标**  
固定答辩用音色、文本与参数，并产出最终回归样音与演示脚本。

> 本节点接管原 LJQ-N1/N2 与原 CXY-N2 演示脚本部分。

**输入**

- Week 3 回归 WAV、听测表与对照结论。
- 已保存音色与 5 条固定回归文本。
- CXY-N1 冻结规则。

**工作**

**A. 演示参数冻结**

- 选定 1 个主演示音色 + 1 个备用音色。
- 选定演示文本：1 条短句（现场生成）+ 2 条固定回归文本。
- 冻结参数：语种、`speed_factor`、`fragment_interval`、情绪标签。
- 记录主 Demo 机与备用机信息、显存要求。

**B. 最终回归样音**

- 用冻结参数生成最终回归 WAV（覆盖 5 条固定文本）。
- 记录路径、参数、耗时、显存与日志；确认全部来自本机本次运行。
- 准备降级素材：同版本预跑 WAV，标注“降级用”，与正式回归分目录存放。

**C. 演示脚本**

- 编写 8–10 分钟演示脚本与分镜，对应 10 步链路。
- 每步写明操作、预期界面、口播要点、时长与失败时的应急动作。

**输出**

- 演示参数包（音色、文本、参数、机器信息）。
- 最终回归 WAV 包 + 记录表 + 降级素材目录。
- 8–10 分钟演示脚本与分镜。

**三个指标**

- **哪些人的工作会影响我？** Week 3 回归结果是硬依赖；CXY-N1 是软依赖。不等待视觉精修。
- **我需要交付什么内容？** 演示参数包、最终回归 WAV 与记录、演示脚本。
- **谁需要等待我完成该工作？** 本人 N4/N5；LJQ-N1/N2 与 WGX-N2 据此工作（非阻断）。

**完成判定**

- 演示参数唯一且可复现，答辩前不再更改。
- 回归 WAV 全部来自本机本次运行；降级素材单独标注，不混入正式证据。
- 脚本时长可控，每步都有应急动作。

**AI 参考提示词**

```text
请帮我完成答辩演示的参数冻结、最终回归与演示脚本。

输入：
- 已保存音色与5条固定回归文本；
- Week 3参数与听测结论；
- 主Demo机：RTX 5060 Laptop，8GB显存。

输出：
1. 演示参数包模板：主/备音色、短句+2条固定文本、语种、speed_factor、fragment_interval、情绪标签、机器信息；
2. 最终回归执行步骤与记录表（路径、参数、耗时、显存、日志）；
3. 降级素材的命名与存放规则（必须与正式证据分离）；
4. 8–10分钟演示脚本与分镜：每步操作、预期界面、口播要点、时长、失败应急动作；
5. 显存紧张时的短句策略。

不要夸大相似度或情绪准确率；不要把降级素材写成现场生成结果。
```

## CXY-N4：功能—证据矩阵与已知限制

**目标**  
把每项对外声明的功能对应到真实证据，并如实列出限制。

**输入**

- LHY-N1 五类失败加固结果。
- LHY-N2 pytest 与 GPU 测试报告。
- LHY-N4 README 技术章节。
- CXY-N2 四态截图、CXY-N3 回归包与听测结论。

**工作**

- 建立功能—证据矩阵：功能项 / 实现状态 / 证据路径 / 备注。
- 实现状态只用三档：已实现、部分实现、未实现。
- 列出已知限制：零样本档案而非训练、换参考实现情绪、无自动情绪 DoD、无水印/公网分享/多用户、MP3 依赖 FFmpeg、显存约束。
- 统一答辩口径：不宣称相似度百分比、情绪准确率或模型级解耦。
- 审查 README / PPT 文案是否与矩阵一致，不一致的以矩阵为准。

**输出**

- 功能—证据矩阵。
- 已知限制清单与答辩口径说明。
- 文案一致性审查结论。

**三个指标**

- **哪些人的工作会影响我？** LHY-N1/N2/N4 与 CXY-N2/N3 是硬依赖。
- **我需要交付什么内容？** 证据矩阵、限制清单和口径说明。
- **谁需要等待我完成该工作？** 本人 N5；全员答辩口径以此为准。

**完成判定**

- 矩阵每行都有可打开的证据路径。
- 没有“已实现”却缺证据的项；部分实现如实标注缺口。

**AI 参考提示词**

```text
请生成功能—证据矩阵与已知限制清单。

输入：
- pytest与GPU测试报告；
- 五类失败加固结果；
- 四页四态截图；
- 最终回归WAV与听测结论；
- README技术章节。

输出：
1. 矩阵表：功能项/实现状态（已实现/部分实现/未实现）/证据路径/备注；
2. 已知限制清单：零样本档案非训练、换参考情绪、无自动情绪DoD、无水印/公网分享/多用户、MP3依赖FFmpeg、显存约束；
3. 答辩口径：可以怎么说、不可以怎么说；
4. README/PPT文案与矩阵不一致时的修正建议。

禁止把未实现写成已实现；禁止编造相似度、情绪准确率或解耦指标。
```

## CXY-N5：终审彩排与 Demo 冻结

**目标**  
用全新实例完整走通演示链路，完成彩排并冻结 Demo。

**输入**

- LHY-N3 全新实例验证记录。
- CXY-N3 演示脚本与参数包、CXY-N4 证据矩阵。
- LJQ-N1 资源检查、LJQ-N2 听测与边界复核、WGX-N1 浏览器兼容、WGX-N2 录屏素材（均为非阻断补充）。

**工作**

- 停止旧服务，启动全新实例，完整走通 10 步链路。
- 人工触发五类典型失败，确认提示真实可读。
- 完成一次 8–10 分钟彩排：CXY 主讲并操作，LHY 现场技术应急。
- 答辩前 24 小时内完成一次资源检查与短句冒烟（LJQ 未交付时自行完成）。
- 发布终审结论并冻结 Demo，写入 `Decisions.md`。
- 提交 README、演示视频、PPT；内容与证据矩阵一致。

**输出**

- 终审彩排记录与五类失败现场结果。
- Demo 冻结决议（含冻结时间点与例外规则）。
- 最终交付物清单：README、视频、PPT、证据索引。

**三个指标**

- **哪些人的工作会影响我？** LHY-N3 与 CXY-N3/N4 是硬依赖；LJQ/WGX 的四个节点是非阻断补充。
- **我需要交付什么内容？** 彩排记录、冻结决议和最终交付清单。
- **谁需要等待我完成该工作？** 全员等冻结生效；此后只修演示阻断级缺陷。

**完成判定**

- 全新实例完整走通一次，非“上次已经跑过”。
- 五类失败均有现场提示证据。
- 冻结后新增主功能一律拒绝，例外必须写入台账。
