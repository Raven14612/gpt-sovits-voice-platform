## LJQ-N1：答辩前资源检查

**目标**  
在答辩前确认主机与备用机可用，避免现场环境问题。

**输入**

- CXY-N3 演示参数包（主 Demo 机与备用机信息、显存要求）。
- [GPU Environment Baseline.md](../../GPU%20Environment%20Baseline.md) §4 只读检查命令。

**工作**

- 答辩前 24 小时内在**备用机**运行只读检查：`nvidia-smi`（驱动、显存空闲）、Python 与 PyTorch 版本、`torch.cuda.is_available()`、`ffmpeg -version`、模型与 ASR 目录是否存在。
- 确认备用机保存了同版本回归 WAV，可作为降级素材。
- 若备用机可运行，跑 1 条短句合成作为可用性确认。
- 填写检查表；任一项不可用直接标注，不做修复尝试之外的改动。

**输出**

- 答辩前资源检查表（含检查时间、机器、逐项结论）。
- 备用机降级素材路径确认。

**三个指标**

- **哪些人的工作会影响我？** CXY-N3 参数包是软依赖；只读检查可提前开始。
- **我需要交付什么内容？** 资源检查表与降级素材路径。
- **谁需要等待我完成该工作？** 无人硬等待。CXY-N5 会核对；未交付时 CXY 自行完成。

**完成判定**

- 检查时间在答辩前 24 小时内，结论来自本机命令输出。
- 每项都有明确“可用 / 不可用”，不写“应该没问题”。
- 交付格式：`[LJQ-N1] 检查表路径 + 一行结论 + 不可用项`，无需等待回复。

**AI 参考提示词**

```text

需要检查：

3. ffmpeg -version；
4. 预训练权重与ASR模型目录是否存在；
5. 同版本降级回归WAV是否就位；
6. 1条短句合成的最小验证步骤。

输出：逐项检查表（命令/期望结果/实际结果/可用与否）与填写说明。

```

## LJQ-N2：最终听测与算法边界复核

**目标**  
对最终回归样音做人耳确认，并复核答辩中的算法表述是否夸大。

**输入**

- CXY-N3 最终回归 WAV 包。
- CXY-N4 已知限制清单与答辩口径说明。

**工作**

**A. 最终听测**

- 对最终回归 WAV 逐条打勾：可懂度、音色相似、明显失真、音色漂移。
- 标出最适合现场播放的 2 条，以及不建议播放的条目及原因。
- 只做描述性判断，**不写百分比**。

**B. 算法边界复核**

- 逐句检查 CXY-N4 的答辩口径，标注是否存在夸大表述。
- 重点核对四点：是零样本参考而非训练、情绪靠换参考而非模型解耦、官方静音阈值切分而非自研 VAD、未做相似度或情绪准确率评测。
- 发现问题只标注并给出建议措辞，**不直接改文档**。

**输出**

- 最终听测表 + 推荐播放条目。
- 算法边界复核意见（逐条：原句 / 是否夸大 / 建议措辞）。

**三个指标**

- **哪些人的工作会影响我？** CXY-N3 回归包与 CXY-N4 口径说明是启动条件。
- **我需要交付什么内容？** 听测表与复核意见。
- **谁需要等待我完成该工作？** 无人硬等待。CXY-N5 会采纳或驳回；未交付时 CXY 自行复核。

**完成判定**

- 听测为人工勾选，不使用 AI 打分。
- 复核意见逐条对应原文，可直接采纳。
- 交付格式：`[LJQ-N2] 听测表/复核意见路径 + 一行结论`，无需等待回复。
