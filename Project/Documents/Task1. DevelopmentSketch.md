# Task1. 初步开发计划安排

## 1. 项目定位、目标与创新

### 1.1 项目定位

本项目基于 GPT-SoVITS 的 GPT 韵律建模与 VITS 声码器，建设一个面向授权音频的“小样本音色克隆、可控情感合成与安全追溯”演示系统。

参考项目 `Reference-Project/GPT-SoVITS-main/` 提供模型、训练脚本、音频处理工具、Gradio WebUI 和 `api_v2.py` 推理接口；本项目在其上增加业务编排和四项增强能力：

1. 约 10 分钟授权语音的少样本音色适配；
2. 音色与韵律的可控解耦；
3. 自动/手动情感控制；
4. 生成前拦截、生成后检测和数字水印的语音安全防护。

本项目不重新训练 GPT-SoVITS 基础模型，而是采用“官方模型复用 + 适配层开发 + 可插拔增强模块”的路线。凡是尚未通过真实音频验证的能力，均标记为实验功能，不以架构图或模拟结果代替验收。

### 1.2 总体目标

用户能够完成以下闭环：

```text
上传并确认授权音频 → 切分/降噪/ASR/校对 → 生成标准数据集
→ 约 10 分钟少样本适配 → 注册音色版本 → 文本+情感参数
→ 音色/韵律控制合成 → 敏感词检查+生成标识+数字水印
→ 试听、下载、检测和追溯
```

### 1.3 本项目的可陈述创新点

| 创新点 | 实现方式 | 创新性质 | 验收证据 |
|---|---|---|---|
| 小样本音色资产化 | 将约 10 分钟语音处理为可复用数据集，训练后以 `voice_id/version` 注册 GPT 与 SoVITS 成对权重 | 工程与产品创新 | 重启后仍可加载并合成 |
| 音色—韵律双通道控制 | 音色由固定权重/参考音频决定，韵律由情感向量、风格片段及语速/音高/能量参数决定 | 模型适配创新 | 固定音色仅改变韵律参数时输出变化可测 |
| 自动/手动情感控制 | 文本情感分类得到标签和强度；用户可覆盖标签，统一映射为可审计的风格参数 | 应用算法创新 | 至少 4 类情感、3 档强度可重复生成 |
| 全链路语音安全 | 文本敏感词拦截、输出生成标识、可检测水印和生成记录绑定 | 安全工程创新 | 命中词拒绝/确认；水印检测有实测结果 |
| 可追溯音色与结果 | 保存数据授权、模型版本、参考音频、情感参数、检测结果和水印 ID | 平台治理创新 | 任意输出可反查输入、模型和授权 |

> “90% 音色相似度”“情感识别准确率 80%”等只能作为研究目标，必须先定义数据集、评测方法和基线，不能直接写成已实现功能。

## 2. 功能范围与交付分级

### 2.1 必须实现（增强版 MVP）

1. **数据准备**：上传、格式/时长/采样率校验、授权确认、切分、可选降噪、ASR 初标、人工校对，生成 GPT-SoVITS 标准 `.list`。
2. **10 分钟少样本音色适配**：以 8–15 分钟有效语音为目标区间，复用官方 1A/1B/1C 特征提取和 `s1_train.py`、`s2_train.py`；成功后保存 GPT `.ckpt` 与 SoVITS `.pth`。
3. **零样本回退**：训练失败或耗时过长时，仍可用约 5 秒参考音频完成零样本 TTS，保证演示链路可用。
4. **音色—韵律控制**：固定音色权重，支持风格参考片段、情感标签、强度、语速、音高、能量和停顿参数；记录每次参数。
5. **情感控制**：至少支持中性、开心、悲伤、愤怒/严肃四类标签；提供自动文本分类和手动覆盖两种模式。
6. **语音安全防护**：敏感词预检、授权确认、生成标识、可检测数字水印、结果审计记录。
7. **业务界面与 API**：上传、任务进度、音色列表、情感控制、合成、试听、下载、检测和历史追溯。

### 2.2 增强目标（有时间再做）

- 风格参考音频库和相似风格检索；跨语言情感迁移；水印鲁棒性测试；音色相似度客观指标和 MOS；用户、音色权限和限时分享。

### 2.3 不纳入本期

- 从零自研 GPT/VITS 或替换其核心训练目标；大规模并发训练、多 GPU 调度和云端多节点；未经授权的第三方音色；仅凭示意代码宣称已实现 GRL 对抗解耦、90% 相似度或不可攻破水印。

## 3. 四项核心能力的技术方案

### 3.1 约 10 分钟小样本音色克隆

**复用能力：** `tools/slice_audio.py`、`tools/asr/`、`GPT_SoVITS/prepare_datasets/`、`GPT_SoVITS/s1_train.py`、`GPT_SoVITS/s2_train.py`。

**新增工作：** 上传质量检查；以 `voice_id`/`exp_name` 隔离数据、日志和权重；将官方 subprocess 封装成可恢复任务；训练后校验 GPT/SoVITS 版本和文件完整性；固定文本回归试听并提供零样本回退。

10 分钟是数据量目标，不保证任意录音达到相同相似度。验收记录有效分钟数、训练耗时、显存、失败阶段和听测结论。

### 3.2 音色—韵律解耦

GPT-SoVITS 原生支持参考音频和提示文本，但不把“画双分支架构图”当作已完成的解耦算法，采用分层实现：

**MVP：参数化解耦。** 音色通道固定 `voice_id` 权重和参考音色；韵律通道使用风格参考片段，或情感标签、强度、语速、音高、能量、停顿参数；保存 `speaker_id`、`style_id` 和参数，做固定音色切换风格的对照实验。

**增强：风格向量适配。** 从带情感标签语音提取 mel、F0、能量、时长统计量，建立风格向量到参考条件/后处理参数的映射，并验证音色相似度与韵律变化能否分离。

**预研：显式解耦模型。** 用说话人/韵律分类损失做对比实验；如需 GRL/对抗训练，单独建立实验分支，不修改生产模型；只有具备训练数据、基线和指标时才使用“解耦模型”表述。

### 3.3 自动/手动情感控制

自动模式由文本情感分类器输出 `emotion`、`intensity` 和置信度；低置信度回退中性。手动模式允许覆盖标签和 0–1 强度，并调整语速、音高、能量和停顿。统一控制对象示例：

```json
{"emotion":"sad","intensity":0.7,"speed":0.92,"pitch_semitone":-1.0,"energy":0.85,"pause_scale":1.15}
```

MVP 优先使用可解释的参考风格和韵律参数映射，不承诺 GPT-SoVITS 原生接口已有独立情绪旋钮；效果不稳定时保留标签、参考音频和实验记录并标记为实验能力。

### 3.4 语音安全防护

1. **敏感词拦截**：合成前规范化、分词和词库匹配，支持拒绝、人工确认或安全改写，记录规则版本。
2. **生成标识**：WAV 元数据和数据库写入 `generation_id`、模型版本、时间和授权信息，界面明确提示 AI 生成。
3. **数字水印**：优先评估 AudioSeal；不适配时使用可检测的扩频/频域水印实验方案，密钥由服务端配置管理。
4. **水印检测**：提供检测接口，报告检测概率、载荷 ID 和版本；测试 WAV/MP3、加噪、重采样和裁剪。
5. **授权与审计**：上传确认授权范围和保存期限；音色、参考音频、输出和水印 ID 建立关联；删除任务时清理中间文件。

安全验收强调“可检测、可追溯、可解释”，不宣称水印绝对不可移除。

## 4. 总体架构与目录

```text
Project/
├─ backend/
│  ├─ api/                 # 上传、任务、音色、TTS、情感、安全、追溯接口
│  ├─ services/            # 任务队列、权限、审计、结果处理
│  ├─ adapters/gpt_sovits/ # api_v2 客户端与官方脚本适配
│  ├─ modules/emotion/     # 文本情感分类与强度映射
│  ├─ modules/prosody/     # 风格参考、F0/能量/语速参数映射
│  ├─ modules/safety/      # 敏感词、水印、生成检测
│  └─ db/                  # SQLite 模型与迁移
├─ frontend/               # Vue 3 界面
├─ data/{uploads,datasets,voices,outputs,watermarks}/
├─ tests/                  # 单元、接口、集成和回归测试
├─ Documents/              # 设计、接口、测试和演示文档
└─ deploy/                 # Windows/Docker 配置
```

运行时数据和模型权重不得提交代码仓库。业务层只记录官方日志和权重真实路径，不改造训练产物格式。

## 5. AI 工具协作与研发规范

项目采用“AI 加速、人工决策、真实环境验证”的方式。AI 生成的代码、配置、测试结论和语音效果不能直接作为完成依据，必须回到真实仓库、官方文档和真实模型验证。

### 5.1 工具分工

| 工具类别 | 用途 | 必须保留的证据 |
|---|---|---|
| AI 编程助手 | 阅读仓库、实现适配层、补测试和重构 | 代码差异、测试输出、变更记录 |
| 第二种通用大模型 | 复核接口、路径安全、并发、资源释放和异常处理 | 审查清单、采纳/拒绝理由 |
| AI 搜索/联网工具 | 定位 GPT-SoVITS、FastAPI、PyTorch、CUDA 官方资料 | 官方链接、访问日期、版本号 |
| AI 文档/UI 工具 | 草拟接口文档、页面布局和演示材料 | 来源、人工修订记录 |
| 产品 AI 模块 | 情感分类、ASR、人声处理和水印实验 | 模型版本、输入、参数、输出 |

### 5.2 使用边界

- 不向公共 AI 服务上传密钥、`.env`、个人信息、未脱敏源码或未经授权的声音数据。
- 不直接执行 AI 建议的未知脚本、安装命令或破坏性命令。
- 不用 Mock 音频替代开发、里程碑或演示环境中的真实模型输出；Mock 只用于隔离外部进程的接口测试。
- 依赖版本、API 参数、许可证和安全结论必须由官方资料或源码核验。
- 音色授权、隐私、安全策略和最终发布决定由人工审核。

### 5.3 最小复核流程

1. AI 编程助手以本地 `webui.py`、`api_v2.py` 和官方脚本为实现真值来源。
2. 第二种大模型审查路径白名单、subprocess 退出码、GPU 互斥、状态一致性和水印密钥处理。
3. 先生成并审查正常、异常、边界测试，再实现功能并在真实环境复验。
4. 文档和演示材料由 AI 起草，开发者核对每项结论、日志和音频证据。

## 6. 关键数据模型与接口

### 6.1 音色模型

`voice_id`、`version`、`status`（`training/ready/failed/disabled`）、GPT/SoVITS 成对权重绝对路径、参考音频、`prompt_text/prompt_lang`、`effective_minutes`、`exp_name`、`consent_id`。

### 6.2 合成与安全记录

```text
TTSJob: job_id, voice_id, text, text_lang, emotion_control,
        style_ref, prosody_params, status, output_id, error
Output: output_id, generation_id, wav_path, watermark_id,
        safety_result, created_at
Audit: consent_id, operation, actor, policy_version, timestamp
```

### 6.3 API 草案

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/audio/upload` | 上传并校验授权音频 |
| POST | `/api/datasets` | 创建切分/ASR/特征任务 |
| POST | `/api/voices` | 创建 10 分钟少样本训练任务 |
| GET | `/api/voices` | 查询音色、版本、状态和授权摘要 |
| GET | `/api/tasks/{task_id}` | 查询阶段、进度、日志摘要与错误 |
| POST | `/api/tts` | 创建带情感/韵律控制的异步合成任务 |
| GET | `/api/outputs/{output_id}` | 试听或下载并返回生成标识 |
| POST | `/api/safety/check-text` | 敏感词预检 |
| POST | `/api/safety/detect-watermark` | 检测上传音频水印 |
| GET | `/api/outputs/{output_id}/lineage` | 查询音色、参数、权重和授权追溯链 |

## 7. 四周实施计划

### 第 1 周：基线闭环与数据质量

锁定 GPU、CUDA、Python、PyTorch、GPT-SoVITS 提交和 `v2Pro`；启动官方 WebUI/API，跑通数据准备到推理；完成上传校验、授权确认、路径白名单和零样本代理；建立情感标签、敏感词库、水印选型和固定回归文本。

**验收：** 零样本链路连续 3 次生成可播放 WAV；准备一套 8–15 分钟授权测试语音；完成基线音色/韵律对照样音。

### 第 2 周：少样本训练与任务编排

封装切分、ASR、1A/1B/1C、`s1_train.py`、`s2_train.py`；实现任务状态、阶段日志、超时、取消和清理；完成一次约 10 分钟训练；注册 GPT/SoVITS 成对权重；完成固定音色下的风格和韵律参数实验。

**验收：** 至少一个音色成功保存并重新加载；失败训练不会注册可用音色；输出可反查任务和权重。

### 第 3 周：情感控制、安全模块与前端

接入文本情感分类器，完成自动/手动标签和强度覆盖；完成敏感词预检、生成标识、水印嵌入和检测接口；Vue 3 完成操作、试听、下载和追溯页；开展同音色不同情感、同情感不同音色对照实验。

**验收：** 4 类情感、3 档强度可生成；命中敏感词按策略拦截；结果可检测水印并展示 `generation_id`。

### 第 4 周：真实环境验证与交付

在全新实例执行单元、接口、GPU 集成和端到端测试；固定 5 条文本、2 个音色、4 类情感进行 3 轮回归听测；测试水印在 WAV/MP3、加噪、重采样和裁剪后的表现；完成部署、用户说明、报告、演示脚本和限制清单。

**验收：** 核心链路连续 3 次执行；四项增强能力均有真实输出和失败记录；未完成研究功能明确标注，不以 Mock 结果交付。

## 8. 测试与量化验收

### 8.1 测试层级

单元测试覆盖音频、路径、状态机、情感映射、敏感词、水印和元数据；接口测试覆盖上传、训练、任务、TTS、预检、检测和追溯；集成测试连接真实 `api_v2.py`；端到端测试使用真实授权音频；人工听测评估音色、可懂度、断句、噪声和情感感知。

### 8.2 建议指标

| 类别 | MVP 指标 | 记录方式 |
|---|---|---|
| 少样本适配 | 有效语音 8–15 分钟成功至少 1 个音色 | 日志和权重 |
| 基础 TTS | 固定文本连续 3 次可播放 | 自动化测试 |
| 韵律控制 | 语速、F0、能量、停顿变化方向与参数一致 | librosa/Praat |
| 情感控制 | 4 类标签、3 档强度可重复生成 | 分类日志+听测 |
| 敏感词 | 命中样例 100% 进入既定策略 | pytest+审计 |
| 水印 | 原始 WAV 检测率目标 ≥95%，转码/加噪单独报告 | 检测脚本 |
| 可追溯性 | 100% 输出可查 voice、权重、参数、授权和水印 ID | 数据库核验 |

相似度、情感准确率和水印鲁棒性必须注明数据集、基线、样本量和条件；样本不足时只能称为“内部验证结果”。

## 9. 风险与应对

| 风险 | 应对 |
|---|---|
| 数据质量不足 | 上传质量评分、人工抽检、零样本回退 |
| 显存争用 | 单 GPU 串行队列、资源锁、超时和取消 |
| 情感控制不明显 | 风格参考片段、声学参数测量、如实记录失败样例 |
| 分类误判 | 置信度、低置信度回退中性、允许手动覆盖 |
| 水印影响音质/易损 | A/B 听测和鲁棒性测试，未验证即标记实验 |
| 权重错配 | 保存系列版本，加载前校验，失败不更新音色 |
| 音色滥用 | 授权确认、保存期限、审计、禁用和删除 |
| 排期过紧 | 每周增量交付，显式解耦训练列为预研 |

## 10. 交付物

可运行 Windows GPU 演示系统；FastAPI + Vue 3 源码；真实授权测试音频、`.list` 数据集和一个可加载音色；情感控制、敏感词和水印检测工具；训练/听测/鲁棒性测试报告；部署、用户说明、演示脚本和功能—证据矩阵。

## 11. 开工前必须确认

GPU 与依赖版本；GPT-SoVITS 提交和模型许可证；测试音频授权范围与保存期限；情感模型和水印方案许可证；敏感词策略；是否需要登录、多人隔离和分享。
