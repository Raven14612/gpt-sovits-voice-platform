# CXY Week 2 节点：数据、评测、文档与验收

## CXY-N1：冻结 DoD 与契约 v1.0

**目标**  
在首个音色正式保存前，冻结音频与音色模块的字段和验收口径。

**输入**

- 总计划与 Week 2 总览。
- Week 1 `contract-v0.1`、问题清单和验收结果。

**工作**

- 定义数据集、跨页、试听、保存和重启恢复的 DoD。
- 定稿 `DatasetManifest`、`VoiceProfile`、`voice.json`、`voices.json`。
- 定稿 `audio_service`、`voice_service` 函数和错误对象。
- 明确不验收合成页、结果页、`history.json` 和情绪追加。

**输出**

- Week 2 DoD。
- `contract-v1.0`。
- 本阶段禁止事项清单。

**三个指标**

- **哪些人的工作会影响我？** Week 1 验收结果是软依赖；可先依据总计划起草，再根据实际问题调整。
- **我需要交付什么内容？** DoD、契约 v1.0 和禁止事项。
- **谁需要等待我完成该工作？** LHY-N1/N2 与 WGX-N1/N2 等字段；首次 `save_voice` 必须等待契约冻结。

**完成判定**

- WGX、LHY、LJQ 确认契约可执行。
- 同一字段在页面、service 和 JSON 中只有一种名称。

**AI 参考提示词**

```text
请依据项目总计划、Week 2总览和Week 1契约，为单体Gradio语音克隆项目起草contract-v1.0。

必须定义：
- DatasetManifest及dataset.list四字段；
- VoiceProfile、voice.json、voices.json；
- audio_service和voice_service函数；
- AppError；
- generate_preview只试听、save_voice才写盘；
- Week 2 DoD。

明确不做：合成页、结果历史、history.json、情绪追加、训练。
只起草文档，不修改代码，不把计划写成已完成。
```

## CXY-N2：授权与失败用例

**目标**  
准备贯穿音频页到音色页的授权检查和失败路径。

**输入**

- CXY-N1 DoD 与契约。
- 授权音频清单。
- LJQ-N1 参考音频规范和 LJQ-N4 失败场景；均为软依赖。

**工作**

- 核对测试音频的来源和使用范围。
- 定义未授权、格式非法、时长越界、ASR失败、文本为空、未试听先保存、模型未加载和 OOM 等用例。
- 为每条用例写操作、期望提示和证据。
- 不包含合成页与结果历史。

**输出**

- 授权抽检表。
- 失败用例表。
- 与 `AppError` 的对照草案。

**三个指标**

- **哪些人的工作会影响我？** CXY-N1 是硬依赖；LJQ-N1/N4 是软依赖，收到真实经验后补充。
- **我需要交付什么内容？** 授权表、失败用例和错误码对照。
- **谁需要等待我完成该工作？** WGX-N4、LHY-N4 可据此联调；CXY-N4 等完整验收用例。

**完成判定**

- 每条用例可以人工执行且结果可检查。
- 不使用 Mock 作为通过证据。

**AI 参考提示词**

```text
请为Week 2编写授权抽检与失败用例。

范围：音频上传→裁剪/切分/ASR→选片→音色试听→保存。
至少覆盖：
未授权、非法格式、时长越界、ASR失败、参考文本空、未试听先保存、模型未加载、OOM。

输出：场景、操作、期望AppError、用户提示、证据类型。
不包含合成页、history或假成功。
```

## CXY-N3：数据集与音色档案抽检

**目标**  
检查数据集、音色档案和全局索引是否符合契约。

**输入**

- CXY-N1 的 schema。
- LHY-N1 数据集样例。
- LHY-N3 音色索引与恢复结果。

**工作**

- 检查 `.list` 四字段、路径和编码。
- 检查 `dataset.json` 与切片一致。
- 检查 `voice.json` 必填字段、授权、参考文件和预览文件。
- 检查 `voices.json` 与 `data/voices/` 一致。
- 记录具体问题和负责人。

**输出**

- 数据格式抽检清单。
- 至少一组真实样例的抽检记录。

**三个指标**

- **哪些人的工作会影响我？** CXY-N1 是硬依赖；LHY-N1/N3 的真实样例是执行抽检的硬依赖。
- **我需要交付什么内容？** 抽检清单、记录和问题单。
- **谁需要等待我完成该工作？** CXY-N4 等格式验收结论；LHY 等需修复的问题。

**完成判定**

- 每个“通过”都指向具体文件。
- 索引与目录不一致时不能判定通过。

**AI 参考提示词**

```text
请根据以下contract-v1.0生成数据格式抽检清单：
<粘贴schema>

检查：
- dataset.list四字段、编码和路径；
- dataset.json segments与切片一致；
- voice.json必填字段、授权、reference.wav、preview.wav；
- voices.json与data/voices目录一致；
- 重启恢复后的索引一致性。

输出检查表与问题记录模板，不生成假样例。
```

## CXY-N4：端到端预演与验收

**目标**  
验收“音频 → 选片 → 试听 → 保存 → 重启恢复”的完整阶段流程。

**输入**

- LHY-N4 集成版。
- WGX-N4 浏览器结果。
- LJQ-N3 真实试听验证。
- CXY-N2/N3 用例与抽检结果。

**工作**

- 现场运行主跨页流程。
- 运行直接上传短参考的备用流程。
- 停止并重启应用，确认音色卡片和索引恢复。
- 抽查失败用例。
- 发出通过、部分通过或失败结论。

**输出**

- 阶段验收表。
- 数据集、试听、档案、索引、重启日志和页面截图证据。
- 阻断问题与负责人。

**三个指标**

- **哪些人的工作会影响我？** LHY-N4 是硬依赖；WGX-N4、LJQ-N3、CXY-N2/N3 在正式验收前必须齐备。
- **我需要交付什么内容？** 验收表、证据清单、结论和问题优先级。
- **谁需要等待我完成该工作？** 全员等待是否进入 Week 3；阻断项负责人等待修复优先级。

**完成判定**

- 每项完成都有现场文件、日志或截图。
- `preview.wav` 不是旧文件或 Mock。
- 合成页与结果历史未实现不计入本阶段失败。

**AI 参考提示词**

```text
请根据Week 2 DoD生成端到端预演脚本。

输入证据：
- dataset.list和dataset.json；
- preview.wav；
- voice.json和voices.json；
- 重启后的音色列表；
- 浏览器截图与失败用例。

输出主流程、短参考备用流程、每步期望结果、证据、通过/部分通过/失败判定和阻断负责人。
明确不验收合成页与history；禁止预录WAV替代现场试听。
```
