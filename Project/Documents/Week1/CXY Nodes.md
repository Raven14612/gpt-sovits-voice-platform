# CXY Week 1 节点：数据、评测、文档与验收

## CXY-N1：冻结范围与验收口径

**目标**  
把本周必须完成与禁止扩展的内容写成可检查的 DoD。

**输入**

- `Project/Documents/newplan.md`
- `Project/Documents/New-Task1. AI Project Execution Plan.md`
- `Week1 Development Guide.md`

**工作**

- 固定四页名称和“侧栏一项对应一个完整页面”。
- 固定阶段验收：一键启动、四页切换、3 条真实 WAV、一次切分/ASR、契约草案。
- 写明本周不做完整业务、训练、独立 API、数据库和 2×2 同屏。

**输出**

- Week 1 DoD。
- 四页导航文案。
- 禁止事项清单。

**三个指标**

- **哪些人的工作会影响我？** 无上游依赖，可以立即开始。
- **我需要交付什么内容？** DoD、导航文案和禁止事项。
- **谁需要等待我完成该工作？** WGX 等导航文案；LHY 等模块边界；LJQ 等真实音频验收口径。

**完成判定**

- 三名接收人确认文案与验收口径。
- 未把训练、水印、独立 API 或第五页带回范围。

**AI 参考提示词**

```text
你是4人学生AI项目的敏捷项目经理。请阅读：
1. Project/Documents/newplan.md
2. Project/Documents/New-Task1. AI Project Execution Plan.md

为Week 1起草Markdown DoD，必须包含：
- 一个app.py启动本地Gradio；
- 顶栏、侧栏四项、右侧一次显示一个页面；
- GPT-SoVITS本机生成3条真实WAV；
- 官方切分和ASR各真实运行一次；
- Python services契约草案；
- 禁止训练、独立Web API、数据库、2×2同屏和假音频。

输出验收项、负责人、证据和通过条件。
只起草文档，不修改代码；不要把计划写成已完成。
```

## CXY-N2：准备授权资产与契约草案

**目标**  
给三条研发线提供统一测试输入与字段名称。

**输入**

- CXY-N1 DoD。
- 已授权的声音来源。
- 四类 service 的范围。

**工作**

- 准备一段零样本短参考和一段切分/ASR 长音频。
- 准备 1 条试听文本和 5 条回归文本。
- 起草 `audio/voice/tts/history` 的函数名、输入、输出和统一错误对象。
- 标明 Week 1 只是 v0.1，Week 2 保存首个音色前冻结。

**输出**

- 授权音频清单与授权说明。
- 固定试听/回归文本。
- `contract-v0.1`。

**三个指标**

- **哪些人的工作会影响我？** CXY-N1 是硬依赖；必须先确定范围和验收口径。
- **我需要交付什么内容？** 授权资产清单、试听/回归文本和契约草案。
- **谁需要等待我完成该工作？** LHY-N2 等函数字段；WGX-N2 等页面字段；LJQ-N3 等 I/O 名称。

**完成判定**

- 声音数据均有授权说明。
- 三名接收人可继续开发，不需要等完整业务实现。

**AI 参考提示词**

```text
请为单体Gradio语音克隆项目起草Week 1服务契约v0.1。

架构：页面直接调用Python services，不使用FastAPI或数据库。
模块：audio_service、voice_service、tts_service、history_service。

请输出：
1. 每个模块3至5个函数名；
2. 每个函数的输入、返回值和错误；
3. AppError(code,message,detail)；
4. 1条中文试听文本和5条安全回归文本；
5. 本周仅冻结命名草案，不实现完整业务。

不得生成假音频，不得引入HTTP路由、数据库或训练任务。
```

## CXY-N3：预演、证据与验收

**目标**  
把四条工作链汇合成可验证的第一周结果。

**输入**

- LJQ-N2 的 3 条 WAV 与日志。
- LJQ-N3 的切分/ASR和算法说明。
- LHY-N4 的集成应用。
- WGX-N4 的浏览器检查与截图（初次预演时为软依赖，正式验收前必须收到）。

**工作**

- 按 DoD 逐项预演。
- 标记通过、部分通过、失败和阻断。
- 收集环境、WAV、切分/ASR、页面、启动与交接证据；环境部分对照 [GPU Environment Baseline.md](../GPU%20Environment%20Baseline.md) 全组矩阵（§6）。
- 发出阶段验收结论。

**输出**

- 集成预演记录。
- 阶段 DoD 结果。
- 证据清单和未完成项。

**三个指标**

- **哪些人的工作会影响我？** LJQ-N3 和 LHY-N4 是硬依赖；WGX-N4 是软依赖，正式验收前必须收到。
- **我需要交付什么内容？** 验收表、证据清单和问题优先级。
- **谁需要等待我完成该工作？** 全员等待是否进入 Week 2；LHY/WGX 等待阻断问题优先级。

**完成判定**

- 每个“已完成”都有真实文件、日志或截图。
- 官方 WebUI 出声但项目未接入时只记“部分通过”。

**AI 参考提示词**

```text
请根据Week 1 DoD生成集成预演脚本和证据清单。

输入：
- 3条GPT-SoVITS真实WAV及日志；
- 一次真实切分和ASR输出；
- app.py启动的Gradio四页壳；
- 浏览器侧栏切换结果；
- services契约草案。

输出：
1. 预演步骤；
2. 每步期望结果与证据；
3. 通过、部分通过、失败判定；
4. 阻断问题负责人和下一步；
5. 禁止用AI结论、Mock或预录素材替代现场验证。
```
