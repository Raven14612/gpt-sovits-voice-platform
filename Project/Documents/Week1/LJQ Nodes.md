# LJQ Week 1 节点：算法与模型基线

## LJQ-N1：锁定环境与上游版本

**目标**  
确认本机实际模型、环境和入口，避免后续更换版本。

**输入**

- 本机 GPU、CUDA、Python 与模型文件。
- GPT-SoVITS 本地项目或实际发布包。

**工作**

- 按 [GPU Environment Baseline.md](../GPU%20Environment%20Baseline.md) 填写个人基线表（§5）并汇总全组矩阵（§6）。
- 确认本机属于 **Track A（40 系）** 或 **Track B（50 系）**，不强行与组员共用同一 conda 环境。
- 记录 Python、PyTorch、CUDA、GPU、GPT-SoVITS 版本与实际目录（版本必须来自本机命令，不是 AI 推测）。
- 检查预训练模型、FFmpeg 和 ASR。
- 确认官方零样本推理入口可启动或导入。

**输出**

- 个人环境基线表（建议路径：`Project/Documents/env/<姓名缩写>-baseline.md`）。
- 全组环境矩阵（LJQ 维护，见基线文档 §6）。
- 实际启动方式和目录。
- 缺失依赖与风险。

**三个指标**

- **哪些人的工作会影响我？** 无上游依赖，可以立即开始。
- **我需要交付什么内容？** 个人基线表、全组环境矩阵和可复现启动方式（模板见 [GPU Environment Baseline.md](../GPU%20Environment%20Baseline.md)）。
- **谁需要等待我完成该工作？** LJQ-N2 硬等待；LHY-N3 软等待模型路径和入口。

**完成判定**

- 其他组员能按记录找到实际目录和入口。
- 版本来自本机命令或文件，不是 AI 推测。

**AI 参考提示词**

```text
我需要在Windows上记录GPT-SoVITS环境基线，团队有RTX 40系和50系混用。
请先阅读 Project/Documents/GPU Environment Baseline.md，再生成只读检查清单，包含：
- 本机属于Track A还是Track B；
- nvidia-smi、Python、PyTorch、torch.version.cuda、GPU型号；
- GPT-SoVITS实际目录和版本来源；
- 预训练权重、FFmpeg和ASR；
- 官方零样本推理入口；
- 导入、CUDA和路径错误的排查顺序；
- 个人基线表与全组矩阵应填哪些字段。

不要猜测版本，不要直接修改环境；所有结论由我运行命令后填写。
```

## LJQ-N2：零样本 TTS 真实基线

**目标**  
证明本机模型能够稳定生成真实语音。

**输入**

- LJQ-N1 环境记录。
- CXY-N2 的授权短参考与试听文本；未交付时可先用已有合法素材。

**工作**

- 用官方零样本流程生成 3 条 WAV。
- 记录参考音频、提示文本、合成文本、参数、耗时、显存和错误。
- 不等待页面或业务代码。

**输出**

- 3 条真实 WAV。
- 推理参数与日志。
- 成功和失败说明。

**三个指标**

- **哪些人的工作会影响我？** LJQ-N1 是硬依赖；CXY-N2 是软依赖，可先用已有合法素材，收到统一资产后再对齐。
- **我需要交付什么内容？** 3 条真实 WAV、推理参数和日志。
- **谁需要等待我完成该工作？** LHY-N3 等真实 TTS 参数；CXY-N3 等验收证据。

**完成判定**

- 3 条 WAV 均由本机本次运行产生且可播放。
- 日志能追溯参考音频、文本和配置。

**AI 参考提示词**

```text
请先阅读我本地GPT-SoVITS版本中的TTS.py和配置，再设计零样本冒烟步骤。

输入：
- 授权参考音频：<路径>
- 参考文本：<文本>
- 合成文本：<文本>
- 实际项目目录：<路径>

输出：
1. 基于当前源码的最小调用；
2. 必填参数及来源；
3. 3次推理记录模板；
4. OOM、路径、语言和权重错误处理；
5. 人工确认WAV可播放的方法。

不要编造API，不修改模型核心，不把示例音频当成功证据。
```

## LJQ-N3：切分/ASR 基线与算法交接

**目标**  
提供 Week 2 音频业务所需的真实 I/O 和失败条件。

**输入**

- LJQ-N1 环境。
- CXY-N2 的授权长音频与契约草案。
- 官方切分和 ASR 工具。

**工作**

- 真实执行一次官方静音/音量阈值切分。
- 真实执行一次 ASR。
- 记录目录、切片命名、转写结果和 `.list` 字段。
- 对照契约草案，列出常见失败原因。

**输出**

- 一组真实切片。
- 一份真实 ASR 输出。
- 算法 I/O 与失败条件说明。

**三个指标**

- **哪些人的工作会影响我？** LJQ-N1 是硬依赖；CXY-N2 是软依赖，收到统一长音频和契约后完成最终对齐。
- **我需要交付什么内容？** 切分/ASR文件、I/O说明和错误建议。
- **谁需要等待我完成该工作？** LHY-N3 等调用结构；CXY-N3 等真实证据。

**完成判定**

- 切分和 ASR 文件实际存在且可打开。
- 明确为官方静音阈值切分，不冒充自研 VAD。

**AI 参考提示词**

```text
请基于我本地GPT-SoVITS源码中的官方切分和ASR工具，帮助完成一次真实基线。

输入音频：<路径>
输出目录：<路径>
服务契约草案：<粘贴相关函数>

输出：
1. 当前源码对应的入口与参数；
2. 切片和ASR输出结构；
3. dataset.list四字段映射；
4. 与audio_service草案的字段对照；
5. Top 5失败原因和建议错误码。

切分是静音/音量阈值方案，不宣称自研VAD；不要生成假ASR结果。
```
