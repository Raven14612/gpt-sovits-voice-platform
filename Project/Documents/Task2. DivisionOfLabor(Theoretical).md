# CXY 队长

## 一、角色目标

负责项目整体统筹与最终交付，确保 GPT-SoVITS 基础能力、小样本音色克隆、情感控制、音色—韵律控制和语音安全模块能够按照 Task1 的范围形成可运行、可验证、可演示的系统。队长不替代算法、后端或前端的具体编码工作，重点负责需求边界、技术决策、进度、风险、集成和验收。

## 二、工作内容

1. 将 Task1 拆解为需求清单、里程碑、责任矩阵和验收证据矩阵，明确“必须实现、增强目标、预研功能”三类范围。
2. 组织确定 GPT-SoVITS 上游提交、`v2Pro` 基线、GPU/CUDA/Python/PyTorch 版本、情感分类方案和水印候选方案。
3. 审核总体架构和模块边界，确认算法模块、FastAPI 后端、Vue 前端、SQLite、文件存储、任务队列及 `api_v2.py` 的接口契约。
4. 主持需求评审和接口冻结，统一 `voice_id`、任务状态、情感控制对象、生成标识、水印 ID、错误码和日志字段。
5. 制定四周迭代计划，跟踪每周完成情况、阻塞问题、资源使用、训练进度和变更请求；对排期冲突进行取舍。
6. 管理授权音频、模型、依赖和第三方组件的合规事项，确认敏感词策略、数据保存期限、密钥管理和演示发布范围。
7. 组织跨角色联调：先验收算法基线和权重，再验收后端接口，最后验收前端闭环；维护问题清单和回归结果。
8. 审核关键质量指标，包括零样本连续运行、10 分钟少样本训练、韵律参数变化、情感可感知度、敏感词拦截、水印检测和结果追溯。
9. 组织全新服务实例上的单元、接口、集成和端到端验收，确认失败任务、超时、取消、重启恢复和路径安全场景。
10. 编写和审核部署文档、用户说明、测试报告、功能—证据矩阵、演示脚本和答辩材料，完成最终演示彩排。

## 三、接收的协作产物

- 接收算法负责人提供的数据质量报告、训练配置、`.list` 数据集、GPT/SoVITS 成对权重、情感/韵律实验结果和已知限制。
- 接收系统开发人员提供的 API 文档、数据库结构、任务状态实现、部署配置、日志和测试报告。
- 接收前端交互人员提供的页面原型、交互流程、组件清单、联调反馈和浏览器端测试结果。

## 四、向其他角色输出的成果

- 向算法负责人输出数据规范、训练验收标准、情感标签体系、固定回归文本和实验优先级。
- 向系统开发人员输出业务需求、接口契约、状态机、数据字段、错误处理和安全合规要求。
- 向前端交互人员输出页面流程、接口说明、状态展示规则、情感控件范围、提示文案和验收样例。
- 向全体成员输出版本计划、会议结论、风险清单、变更记录和最终验收结论。

## 五、AI 辅助方式

- 使用 AI 分析 Task1、参考仓库和会议记录，生成需求拆解、里程碑、风险清单及验收表初稿，再由人工确认。
- 使用另一种大模型交叉审查架构边界、接口一致性、隐私合规、权重许可和排期风险，不直接采纳未经验证的结论。
- 使用 AI 汇总测试日志、训练结果和听测记录，辅助生成测试报告、演示讲稿和答辩问答；所有数字和结论回溯到原始证据。

## 六、角色验收标准

- 四个角色的输入、输出和接口均有书面记录，关键接口已冻结。
- 每周有可运行增量，未完成的功能明确标记为增强或预研，不被误报为已实现。
- 在全新环境完成核心链路验收，问题清单、测试证据和已知限制完整。
- 能独立完成系统演示并说明与 GPT-SoVITS 参考项目的差异、创新点和技术边界。

# LJQ 算法负责人(AI开发)

## 一、角色目标

负责语音数据处理、GPT-SoVITS 音色克隆、情绪化 TTS 适配、音色—韵律控制实验及语音效果评测，向系统提供可加载的模型产物、可复现实验参数和客观/主观评测证据。不负责业务 API、数据库和页面实现。

## 二、工作内容

1. 制定授权音频采集和质量规范，检查有效时长、采样率、声道、静音比例、削波、噪声、说话人一致性和文本覆盖度。
2. 使用官方切分、降噪/人声分离和 ASR 工具处理音频，生成 GPT-SoVITS 标准 `.list`；对 ASR 初标进行人工抽检和校对。
3. 按官方 1A/1B/1C 流程完成特征提取，记录脚本提交、参数、数据量、耗时、显存、日志路径和失败原因。
4. 复用 `s1_train.py`、`s2_train.py` 完成约 8–15 分钟有效语音的少样本训练，保存并校验 GPT `.ckpt` 与 SoVITS `.pth` 成对权重。
5. 使用固定文本进行零样本基线、少样本音色和不同权重版本的对照试听，记录可懂度、音色一致性、噪声、断句和过拟合情况。
6. 设计音色—韵律控制实验：固定音色权重，改变参考风格片段、情感标签、语速、音高、能量和停顿参数，测量 F0、能量、时长等变化。
7. 建立自动情感标签和强度映射方案，至少覆盖中性、开心、悲伤、愤怒/严肃；输出标签、强度、置信度及低置信度回退规则。
8. 评估手动情感控制效果，确定标签覆盖、强度范围和参数边界；记录“可感知、弱感知、无效或失真”的样例。
9. 在独立实验分支验证风格向量适配或 GRL/对抗解耦的可行性；没有基线、数据和指标时不得将预研结果作为生产能力。
10. 配合水印和安全模块进行音质 A/B 听测，提供原始、嵌入水印及转码/加噪后的样音和效果说明。
11. 输出模型卡片和算法限制，说明训练数据授权、模型版本、适用语种、推荐参数、已知失败场景和复现实验步骤。

## 三、接收的协作产物

- 接收队长提供的需求范围、情感标签体系、固定回归文本、验收指标、数据合规要求和实验优先级。
- 接收系统开发人员提供的任务接口、文件路径约定、权重注册字段、状态回调格式和推理调用契约。
- 接收前端交互人员提供的情感控件定义、用户可调参数范围、交互文案和试听对照需求。

## 四、向其他角色输出的成果

- 向队长输出算法方案、数据质量报告、训练日志、成对权重、样音、指标和风险说明。
- 向系统开发人员输出可加载权重的绝对路径/版本、参考音频和提示文本、情感参数 Schema、推荐默认值及错误条件。
- 向前端交互人员输出情感标签和强度选项、参数上下限、效果提示、样音对照组和低置信度/失败提示文案。

## 五、AI 辅助方式

- 使用 AI 生成音频质量检查脚本、ASR 文本清洗规则和数据统计代码，人工检查边界条件后在授权数据上运行。
- 使用 AI 根据真实训练日志分析显存、收敛、过拟合和参数异常，提出调参候选；每个候选必须通过真实训练或回归听测验证。
- 使用 AI 辅助提取 F0、能量、语速和停顿统计，生成听测表和实验报告；不使用 AI 生成的 Mock 音频代替模型结果。

## 六、角色验收标准

- 至少一套授权音频生成合法 `.list`，完成抽检并记录有效分钟数。
- 至少一个音色生成可加载的 GPT/SoVITS 成对权重，能在服务重启后完成 TTS。
- 固定音色改变韵律参数时有可测声学变化和对照样音。
- 自动/手动情感控制至少支持 4 类标签、3 档强度，并提供真实输出、置信度和失败记录。
- 所有模型产物均有版本、来源、参数、许可证和复现说明。

# LHY 系统开发人员(后端开发)

## 一、角色目标

负责业务后端、任务编排、数据持久化、模型服务适配、文件安全和部署，使算法能力通过稳定、可测试的 API 提供给前端。不负责训练算法设计和页面视觉交互。

## 二、工作内容

1. 搭建 Python + FastAPI 服务，定义上传、数据集、音色、任务、TTS、情感、安全和追溯 API。
2. 设计 SQLite 数据模型和迁移，包括 `Voice`、`DatasetJob`、`TTSJob`、`Output`、`Consent`、`Audit`、`Watermark` 等实体及关联关系。
3. 实现上传文件校验、扩展名和 MIME 检查、大小/时长限制、短 ASCII 路径规范化、路径白名单和文件生命周期清理。
4. 编写 GPT-SoVITS 适配层：通过 HTTP 调用 `api_v2.py` 的 `/tts`、`/set_gpt_weights`、`/set_sovits_weights`，通过受控 subprocess 调用切分、ASR、特征提取和训练脚本。
5. 实现 `queued → processing → succeeded/failed/cancelled` 状态机，保存当前阶段、进度、退出码、日志路径、错误摘要和重启恢复信息。
6. 实现单 GPU 串行队列、资源锁、超时、取消、失败清理和推理/训练互斥，防止显存争用和半成品音色注册。
7. 实现音色注册与版本校验：GPT/SoVITS 权重必须同系列成对加载；任一步失败不得更新当前可用音色。
8. 实现情感控制参数校验和默认值合并，将前端的自动/手动控制转换为算法模块需要的结构，并保存原始参数和最终参数。
9. 接入敏感词预检、生成标识、数字水印嵌入/检测及审计记录；水印密钥从服务端配置读取，不写入代码和日志。
10. 实现输出音频落盘、下载/试听响应、生成 ID、模型版本、参数、水印 ID 和授权记录的追溯接口。
11. 编写部署配置和启动脚本，支持 Windows 本地 GPU，保留 Docker 可选配置；补充环境变量、目录权限、日志脱敏和服务健康检查。
12. 编写单元测试、FastAPI TestClient 接口测试和可选 GPU 集成测试，覆盖正常、异常、边界、超时、重启恢复和路径攻击场景。

## 三、接收的协作产物

- 接收队长提供的接口契约、状态机、字段规范、错误码、安全策略、版本计划和验收样例。
- 接收算法负责人提供训练脚本参数、权重路径、参考音频/提示文本、情感参数 Schema、推理限制和水印音质要求。
- 接收前端交互人员提供页面调用顺序、字段绑定、轮询频率、错误展示和音频下载/播放需求。

## 四、向其他角色输出的成果

- 向队长输出 OpenAPI 文档、数据库 ER/字段说明、部署说明、日志、测试结果和集成问题清单。
- 向算法负责人提供稳定的文件路径、任务回调、训练触发和推理接口，反馈真实运行错误、耗时和资源占用。
- 向前端交互人员输出可调用的 API 地址、请求/响应示例、状态枚举、错误码、试听下载地址和追溯数据结构。

## 五、AI 辅助方式

- 使用 AI 根据接口契约生成 FastAPI 路由、Pydantic Schema、数据库 CRUD 和 pytest 初稿，人工补充权限、路径和并发边界。
- 使用 AI 分析真实异常日志、subprocess 退出码、HTTP 响应和 CUDA 错误，提出排错路径；修复后必须重启服务并复测。
- 使用 AI 生成安全测试、状态机测试和接口契约测试，人工审查是否覆盖路径穿越、重复提交、超时、取消和服务重启场景。

## 六、角色验收标准

- 前端只通过业务 API 完成上传、任务查询、音色选择、合成、下载、敏感词预检、水印检测和追溯。
- 任务状态和音色元数据在服务重启后不丢失；失败任务不会产生 `ready` 音色。
- GPT/SoVITS 权重版本、参考音频和提示文本校验有效；训练与推理不会并发争用 GPU。
- 路径、文件、参数、日志和密钥处理通过安全测试；核心 API 单元/接口测试可重复运行。
- 在真实 `api_v2.py` 服务上完成至少一次少样本音色和一次带情感参数的 TTS 集成验证。

# WGX 前端交互人员(前端开发)

## 一、角色目标

负责 Vue 3 演示界面和交互体验，将上传、训练、音色管理、情感控制、安全提示、试听下载和追溯能力组织成清晰可操作的页面。不负责后端业务规则、模型训练和水印算法实现。

## 二、工作内容

1. 根据业务流程设计页面信息架构：音频上传与授权、数据处理/训练任务、音色库、TTS 合成、历史输出、安全检测和结果追溯。
2. 制作低保真原型和组件清单，明确空状态、加载状态、成功、失败、超时、取消、权限提示和不可用音色状态。
3. 实现音频上传组件，展示格式/时长/质量校验、授权确认、上传进度和错误原因；禁止绕过后端直接访问模型服务。
4. 实现任务状态页和轮询逻辑，展示 `queued`、`processing`、`succeeded`、`failed`、`cancelled`、当前阶段、进度、日志摘要和重试提示。
5. 实现音色列表和详情页，展示 `voice_id`、版本、有效分钟数、训练状态、参考音频、推荐语种、授权摘要和可用操作。
6. 实现 TTS 合成表单：文本、语种、音色、参考风格片段、自动/手动情感模式、情感标签、强度、语速、音高、能量和停顿控件。
7. 实现情感控件联动：自动模式显示分类标签和置信度，低置信度提示中性回退；手动模式允许覆盖标签和强度，并校验参数范围。
8. 实现音频播放器，支持播放/暂停、进度拖动、音量、下载、生成标识展示和同文本多版本 A/B 对照试听。
9. 实现敏感词预检提示、授权/安全提示、水印检测结果、AI 生成标识和失败原因的可理解展示，不暴露密钥和内部绝对路径。
10. 实现历史记录和追溯页，展示输入文本、音色版本、情感/韵律参数、生成时间、水印 ID、检测结果和输出文件。
11. 完成响应式布局、基本无障碍支持、中文文案统一、浏览器兼容性检查和关键流程的前端测试。
12. 配合队长完成演示路径、演示数据、页面截图、操作手册和答辩展示材料。
